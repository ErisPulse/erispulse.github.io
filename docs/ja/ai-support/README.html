AI 支援開発

ErisPulse は、AI が最新のフレームワーク仕様に基づいてコードを生成できるようにする、2つの補完的な AI 支援開発の方法を提供します：

  • マテリアルドキュメント：1つの大きな Markdown で、コンテキストを一括投入します。プロジェクト全体の開発に適しています
  • MCP サーバー：AI が必要に応じて公式ドキュメントを検索できるようにします。日常のコード補完や API 参照に適しています
マテリアルドキュメント MCP サーバー
形式 1つの大きな Markdown、一括投入 AI によるオンデマンド検索
コンテキストコスト 高い（token を消費） 低い（関連部分のみ取得）
鮮度 バージョンリリースに合わせて更新 リアルタイム（GitHub から取得 + キャッシュ）
適する場面 コンテキストウィンドウが大きい、プロジェクト全体の開発 日常のコード補完、API 参照
クライアント あらゆる AI ツール MCP 対応クライアントのみ

両者は矛盾しません：大規模プロジェクトの開発では同時に使用できます——マテリアルドキュメントを土台とし、MCP で抜け漏れを補完します。

マテリアルドキュメント

マテリアルドキュメントは prompts/ ディレクトリにあり、開発シーンに応じて3種類に分かれています：

ドキュメント シーン 説明
ErisPulse-ModuleDev.md モジュール開発 モジュール開発の全フローをカバー（イベント処理、ルーティング、ライフサイクルなど）
ErisPulse-AdapterDev.md アダプター開発 モジュール開発の内容に加え、アダプターのコア概念、SendDSL、プラットフォーム適合ガイド
ErisPulse-Full.md フルスタックリファレンス 上記すべての内容 + 完全なユーザーガイドと API リファレンスのコレクション

入手方法：prompts/ ディレクトリから直接取得（ドキュメントと同期更新）、または GitHub Releases から対応バージョンをダウンロードします。

使用方法

  1. 目的に応じてドキュメントを選択（モジュール → ModuleDev、アダプター → AdapterDev、複雑な要件 → Full）
  2. ドキュメントの内容をコンテキストとして AI に提供：IDE 内ではワークスペースに置き、チャット型では直接貼り付け、API 呼び出しでは system message として注入
  3. 以下のテンプレートで要件を記述します。具体的であるほど生成品質が高くなります

Agent Skills

Agent Skills は、AI コーディングエージェント（ZCode / Claude Code など）向けのスキルパッケージです：各スキルは1つのディレクトリ（SKILL.md + frontmatter）で構成され、エージェントは description に基づいて自動的に発見し、必要に応じてロードします——タスクに関連する場合にのみ対応するセクションを読めばよく、全文を投入する必要はありません。

スキルは skills/ ディレクトリにあります（マテリアルドキュメントと同期生成）。各 SKILL.md の冒頭には行番号アウトラインが付いています：各セクションの開始・終了行番号が示されており、AI は必要な部分だけを読むことができます。

デプロイ方法

  1. skills/<言語>/ ディレクトリからスキルを取得（または対応バージョンの artifact をダウンロード）
  2. スキルディレクトリをエージェントのスキルディレクトリにコピー（ツールの規約に従ってください。例：.zcode/skills/、.claude/skills/）
  3. その後、エージェントが関連タスクに遭遇すると自動的にロードがトリガーされ、手動での参照は不要です

アウトライン例

## 内容アウトライン
AI がオンデマンドで読み取り：必要なセクションだけを読めば十分で、全文をロードする必要はありません。

- 遅延ロードとスリープ: 18-29 行目
- 概要: 30-38 行目
- イベント駆動の遅延アクティベーション（activate_on）: 55-132 行目

スキルは CI によって自動ビルドされます（python -m scripts.tools gen skills）。手動で編集しないでください。

MCP サーバー

ErisPulse はドキュメント検索用の MCP Server を提供しており、AI コーディングアシスタント（MCP 対応であればどれでも）がコードを書く際に直接 ErisPulse 公式ドキュメントを検索・閲覧できるようになります。

接続方法は2つあります：ローカルプロセス（推奨）または公式オンラインエンドポイントです。ツールセットは共通です：

ツール パラメータ 説明
search_docs query (必須), top_k?=5, lang?=zh-CN BM25 キーワード検索。複数のキーワードを一度に渡せます
read_document doc_path (必須), lang?=zh-CN 単一ドキュメントの完全な Markdown を読み取る
list_documents lang?=zh-CN 現在の言語のすべてのドキュメントのタイトル、パス、カテゴリを一覧表示
list_languages — ドキュメントがサポートするすべての言語とドキュメント数を一覧表示

サポート言語：zh-CN / en / zh-TW / ja / ru。検索のコツ：文章全体ではなく複数のキーワードを使用します。たとえば コマンド登録 イベントリッスン は コマンドを1つ登録する方法 よりも良い結果が得られます。

方法1：ローカルプロセス（推奨）

インストール後、ローカルで直接起動します：

npm i -g @erisdev/mcp-server   # グローバルインストール → epsdk-mcp コマンドが使用可能に
epsdk-mcp --server               # MCP サービスを起動；初回実行時にドキュメントを ~/.cache/erispulse-mcp/docs へ自動取得

グローバルインストールしなくても、npx で直接実行できます（インストール不要）：

npx @erisdev/mcp-server --server

ローカルにドキュメントディレクトリがある場合はそれを指定します（オフライン）：

ERISPULSE_DOCS_DIR=/path/to/erispulse/docs epsdk-mcp --server

MCP クライアントでは stdio トランスポートで設定します。標準的なキー値（command + args で上記の起動方法を指定；具体的な設定場所と形式は各クライアント自身の MCP 接続ドキュメントを参照）：

{
  "command": "epsdk-mcp",
  "args": ["--server"]
}

または

{
  "command": "npx",
  "args": ["@erisdev/mcp-server", "--server"]
}

方法2：公式オンラインエンドポイント

ローカルでプロセスを起動したくない場合は、公式ホスティングの mcp.erisdev.com に接続します。MCP クライアントでは HTTP トランスポートで設定します：

{
  "url": "https://mcp.erisdev.com/"
}

サービスはデフォルトで公開されており、Token は不要ですが、IP レート制限があります（IP ごとに毎分 60 回）。公式エンドポイントはいつでも停止される可能性があるため、本番ワークフローでは方法1（ローカルプロセス）またはセルフホスティングを推奨します。

よくある質問

生成されたコードが期待どおりでない場合は？ 完全なドキュメントが提供されているか確認します；要件に入出力例や境界条件などの詳細を追加します；AI に段階的に生成させます（まずスケルトンを作り、その後機能を補完）；examples/ ディレクトリのサンプルを補足コンテキストとして参考にします。

MCP 接続後に AI が search_docs を呼び出さない場合は？ クライアントがその server をロードしているか確認します（クライアントを再起動するとツールが有効になっているのが確認できます）；一部のクライアントでは、prompt に「ErisPulse ドキュメントツールを使って API を確認する」ことを明示的に指示する必要があります。
