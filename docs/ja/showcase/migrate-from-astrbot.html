AstrBot から ErisPulse への移行ガイド

Tip

このドキュメントを読むタイミング：既に AstrBot ロボットをお持ちで、それを ErisPulse に移行したい場合に読んでください。新規構築の場合は、クイックスタートをご覧ください。

結論から言うと：プラットフォームの接続、モデル、人格、知識ベースはそのまま移行できます。ただし、AstrBot のプラグインは移行できません——両方のプラグイン API は完全に異なっており、ErisPulse のモジュール規格に従って再作成する必要があります。データは自動的に移行されません。

概念対照

AstrBot における ErisPulse における 説明
プラットフォームアダプター（QQ/微信/Telegram…） プラットフォームアダプター 概念は同一。ErisPulse では該当するアダプターをインストールするだけ
LLM Provider（API Key、モデル） QvQChat モデルプール いずれも OpenAI 兼容の接続をサポート。QvQChat はモデルプールの自己修復と難易度ルーティングをサポート
人格 Persona QvQChat 人格システム システムプロンプト + 会話開始文 + ツールホワイトリスト。手動で移行する必要がある
知識ベース QvQChat 知識ベース 世界書式のキーワードトリガー + ベクトル検索。再インポートが必要
WebUI Dashboard モジュールの起動・停止、設定、ログ、イベント監視。QvQChat には別途コントロールパネルがある
プラグイン モジュール API が異なるため、再実装が必要（以下参照）
管理者/ホワイトリスト 3次元作用域 + モジュール固有の権限（例: QvQChat の admins） 権限モデルがより細かく、各モジュールごとに設定可能

マイグレーション手順

  1. フレームワークの構築：クイックスタートに従ってプロジェクトを初期化します（Docker または pip のどちらでも構いません）。Dashboard をインストールします。
  2. プラットフォームの接続：epsdk install コマンドで、以前使用していたプラットフォームアダプタをインストールします（QQエコシステムの場合は OneBot アダプタを、Telegram の場合は Telegram アダプタをインストールします……）。ログイン方法とプロトコル実装の選択は、AstrBot 時期と同じです。
  3. エージェントのインストール：epsdk install ErisPulse-QvQChat を実行し、モデルプールに以前の Base URL / API Key / モデル名を入力します。
  4. 人格と知識ベースの移行：人格は QvQChat の人格ページで1つずつ新規作成します。知識ベースのドキュメントは再インポートします。
  5. プラグインの再作成：次の節の対照表に従い、元のプラグインの「コマンド → 処理ロジック」を ErisPulse モジュールに翻訳します。

プラグインの書き換え対照

同じ「/ping を受信して pong を返す」プラグインを、それぞれのフレームワークで書いた例：

AstrBot プラグイン（AstrBot のドキュメントを基準とした例）：

from astrbot.api.event import filter, AstrMessageEvent

@filter.command("ping")
async def ping(self, event: AstrMessageEvent):
    yield event.plain_result("pong")

ErisPulse モジュール（実行可能な完全な例、モジュール開発入門を参照）：

from ErisPulse.Core.Event import command

@command("ping", help="テスト：ロボットがオンラインか確認")
async def ping_handler(event):
    await event.reply("pong")

主な違い：

  • イベントモデル：AstrBot は各プラットフォームごとに独自のイベントオブジェクトを使用；ErisPulse は OneBot12 の統一イベントを使用し、event.reply / SendDSL はすべてのプラットフォームで一貫した動作を行う
  • パッケージ構造：ErisPulse モジュールは標準的な Python パッケージであり、epsdk create module で作成されたテンプレートを使用し、PyPI およびモジュール市場に公開される
  • スケジュールタスク / ストレージ：Cron モジュールをインストールするか、フレームワークの内蔵ストレージ API を直接使用する。外部依存ライブラリを追加する必要はない

建議される移行戦略

並行双走り：ErisPulse ロボットをまずテスト用のグループに接続し、すべての機能が正常に動作することを確認してから、本番グループに切り替えます。両方のプラットフォームのアカウント体系は独立しており（それぞれのプロトコル実装/Token）、互いに影響を与えず、ロールバックコストも低くなります。

Note

AstrBot のプラグイン API と機能リストは継続的に進化しています。本ページの対照は一般的な概念を主に扱っています。具体的に特定のプラグインが ErisPulse に同等のものがあるかどうかは、まずモジュール市場で検索してみてください。見つからない場合は、前節に従って再実装してください。多くの業務用プラグインは、ErisPulse では実装がさらに短くなる傾向があります。
