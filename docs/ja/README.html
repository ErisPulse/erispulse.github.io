ErisPulse ドキュメント

ErisPulse はイベント駆動型のモジュラーアシンクロナスなロボットフレームワークです。ビジネスコードは一度だけ書けば、アダプタを介して QQ、Telegram、Kook、雲湖など複数のプラットフォームにデプロイできます。プラグインシステム、ホットリロード、そして開発者向けの完全なツールチェーンがすぐに利用できます。

初めて使う？ 5分で始めるを直接見てください — インストールから最初のロボットの実行まで、一連の流れを完了します。

目的に応じて、対応する学習パスを選択してください。各パスは浅いところから深いところへ順序付けされています。

Important

すべてのドキュメントを読む必要はありません。 大多数の開発者は L1コア5編（約1〜2時間）を順番に読めば、90%の機能を独自に開発できます。残りのドキュメントは特定のシナリオで必要なときに查阅する資料です — 必要なときに翻ってください。各編の冒頭には「いつこの編を読む必要があるか」が明記されています。

L1コア5編: モジュール開発入門 → 基本概念 → Eventラッパークラス → 設定ファイルの説明 → 例外のキャッチ

メッセージと対話 Conversation多輪対話 · セッション受信箱 · MessageBuilder · 国際化 セッション排他リースが分からないと、2つのモジュールが同時に同じユーザーの返信を待つと、お互いに打ち消し合う

グレーディングと影 影モジュールとグレーディングプロセス 5つの隔離ゲートを知らないままプロセスを進めると、影モジュールの出力が本番ユーザーに外漏する

概念関係表

どのサブシステムが何を担当しているかが分からないときは、この表で照合してください：

サブシステム 何を回答するか 一言口訣
通信（module-communication） モジュール間でどう呼び合うか、どうイベントを送るか？ 跨モジュールはmodule.callを使う；相手がmeta.servicesを宣言していればホワイトリスト内のメソッドしか呼べない
権限（scope） 誰がこのモジュールを使えるか、誰がイベントをトリガーできるか、どのアクションが実行できるか？ 3つのゲート — モジュールバインディング、アイデンティティのアクセス制限、出力制限、すべてはユーザーの設定で決まる
所有（ownership） モジュールがアンロードされた後、開いた接続、タイマー、サブスクリプションはどこに行くのか？ 誰が登録したかが所有者、アンロード時は回収、未使用のリソースは残らない
遅延ロードと休眠（lazy-loading） モジュールはいつ実際にロードされるのか、無使用時はどこに行くのか？ activate_onで必要時に起動、dormant_afterで無使用時は休眠
インタラクション（interaction） ユーザーの次の返信をどう待つのか、多輪の入力をどう書くのか？ wait_replyで1つを待つ、.got()で連鎖して複数を収集、リースで競合を防ぐ
影とグレーディング（shadow） 新しいモジュールを本番に影響を与えることなく試運転するには？ 影モジュールはコピーを受け取り、出力は記録だけ、promoteで人間が確認して本番に移行
ストレージ（storage-backends） データはどこに保存されるのか、バックエンドはどのように変更するのか？ 一貫したストレージAPI、sqlite / mysql / postgresは設定で切り替えられる

開発方法

ErisPulseは2つの開発方法をサポートしています：

  • モジュール開発（推奨）：独立したモジュールパッケージを作成し、パッケージマネージャーでインストールすることで、配布や管理が容易になります。
  • 埋め込み開発：プロジェクト内で直接ハンドラを記述し、プロトタイプの作成に適しています。詳しくは快速开始を参照してください。
