ErisPulse ドキュメント

ErisPulse はイベント駆動型のモジュール式非同期ボットフレームワークです。ビジネスコードは一度だけ書けば、アダプターを通じて QQ、Telegram、Kook、云湖（Yunhu）など複数のプラットフォームにデプロイでき、プラグインシステム、ホットリロード、完全な開発者ツールチェーンがすぐに使えます。

初めてのご利用ですか？ 5 分クイックスタート を直接ご覧ください —— インストールから最初のボットの実行まで、一気通貫で完了します。

自分に合ったパスを選ぶ

目標に応じて、対応する学習パスを選択してください。各パスの内部は基礎から応用へと順に並んでいます。

Important

すべてのドキュメントを読み通す必要はありません。 大多数の開発者は、L1 コア 5 編を順番に読み終えるだけ （約 1〜2 時間）で、機能の 90% を独自に開発できるようになります。残りのドキュメントは、すべて特定のシナリオ向けの 必要に応じた参照資料です——対応するニーズが生じたときに読めばよく、各編の冒頭には「いつこの編を読むべきか」が記載されています。

L1 コア 5 編：モジュール開発入門 → 基本概念 → Event ラッパークラス → 設定ファイルの説明 → 例外キャッチ

アダプター作者にはさらに以下が必要です：アダプター開発入門 → イベントコンバーター → SendDSL 詳解

シャドウカナリア シャドウモジュールとカナリア昇格 5 つの隔離ゲートを理解しないまま早期昇格すると、シャドウの発信メッセージが実ユーザーへ漏れ出ます

概念の関係一覧表

どのサブシステムが何を担当しているのか分からないときは、この表で当てはまるものを探してください：

サブシステム どんな問題に答えるか 一言まとめ
通信（module-communication） モジュール同士はどうやって相互呼び出しやイベントの宛先指定送信をするのか？ モジュール間は module.call を使う。相手が meta.services を宣言している場合は、ホワイトリスト内のメソッドしか呼び出せない
権限（scope） このモジュールを誰が使えるか、誰がイベントを発火できるか、どんなアクションを実行できるか？ 3 つのゲート——モジュールバインド、ID 准入、発信制限。すべてユーザー設定で決まる
所有（ownership） モジュールのアンロード後、それが開いた接続、タイマー、サブスクリプションはどうなるのか？ 登録した者が所有し、アンロード時に回収。ぶら下がりリソースは残さない
遅延読み込みとスリープ（lazy-loading） モジュールはいつ実際に読み込まれ、アイドル後はどうなるのか？ activate_on で使うときに起床、dormant_after でアイドル時にスリープ
インタラクション（interaction） ユーザーの次の返信をどう待つか、複数ターンの収集はどう書くか？ wait_reply で 1 件待ち、.got() チェーンで複数ターンを収集。リースが競合を防ぐ
シャドウカナリア（shadow） 新バージョンのモジュールを本番に影響を与えずに試験運用するには？ シャドウはコピーを受信し、発信は記録のみ。promote は人の確認があって初めて昇格
ストレージ（storage-backends） データはどこに保存され、バックエンドはどう切り替えるのか？ 同一のストレージ API で、sqlite / mysql / postgres を設定で切り替え

開発方式

ErisPulse は 2 つの開発方式をサポートしています：

  • モジュール開発（推奨）：独立したモジュールパッケージを作成し、パッケージマネージャーでインストールすることで、配布と管理が容易になります。
  • 埋め込み開発：プロジェクト内に直接ハンドラーを記述します。迅速なプロトタイピングに適しています。詳細は クイックスタート をご覧ください。
