バージョンアップと移行ガイド

Tip

このドキュメントを読むタイミング：古いバージョンからアップグレードする前に、コードの変更やデプロイの確認が必要な破壊的変更を確認してください。現在使用しているバージョンから下に進み、該当するセクションを読んでください。パッチ（小更新）は移行作業を含みません。完全な変更履歴は CHANGELOG を参照してください。

バージョン管理規則：パッチバージョン（x.y.Z）には移行作業は含まれません。コードの変更が必要な変更は、マイナーバージョン（x.Y.0）にのみ含まれます。このページでは、2.0.0 以降のすべての破壊的変更をカバーしています（2.5.0 が最初の本番対応バージョンです。1.x から 2.0.0 への移行については、CHANGELOG の 2.0.0 項目を参照してください）。

2.0.x → 2.5.0（リリース準備の要件）

  • ⚠️ 严格モードのデフォルト有効化（レベル 1）：BaseModule / BaseAdapter を継承していない旧コンポーネントはデフォルトで読み込みを拒否します。例外リストは [ErisPulse.framework] strict_mode_exceptions.modules/adapters または strict_mode = 0 の緩和モードをご利用ください。
  • 初回起動時の言語確認インターフェース（i18n 5言語対応）：自動化デプロイの場合は事前に言語を設定する必要があります（ERISPULSE_LANG 環境変数または設定ファイルによる）。
  • C 拡張を含むサードパーティ依存ライブラリ（watchdog / packaging）の削除——aarch64/ARM のインストール互換性が向上しました。requirements に固定バージョンが設定されている場合は、同期してクリーンアップしてください。

2.5.x 系列内の破壊的変更

  • CLI 別名の管理（2.5.5）：ini 別名の削除（install と近すぎるため）、lr は lsr に変更——スクリプト化されたデプロイコマンドも同期する必要があります。
  • 設定 Schema の再構築（2.5.5）：BaseConfig は共通の基本クラス（AdapterConfig は互換性のための別名）、description は i18n 形式をサポート；**AccountConfig 別名の削除**——カスタム設定クラスの継承は確認する必要があります。
  • アダプター設定アクセスの再構築（2.5.5）：self.cfg はリアルタイムで読み取り（self.config は互換性のための別名）、_load_config() / _load_accounts() キャッシュメソッドの削除——これらのプライベートメソッドを直接呼び出すアダプターは self.cfg を使用するように変更する必要があります。
  • コンポーネント発見のデフォルト有効化（2.5.5）：新規インストールのコンポーネントはデフォルトで enabled=true になります。

2.6.x

  • Core/web_status/ の完全削除、外部の看板娘画像と /status-assets の静的マウントを削除——該当ルーティングに依存するデプロイは、ダッシュボードへの移行が必要です。

2.7.x

  • ポートの使用状況が致命的なエラーとなる（2.7.1）：起動前に同期的な事前チェックを行い、sdk.init() は False を返すようになります。ポートの競合は静かに延期されなくなります。デプロイスクリプトはポートが空いていることを保証する必要があります。
  • ストレージ抽象層が非同期のネイティブ契約に変更（2.7.1）：非同期インターフェース（aget / aset / aExecute / atransaction）がネイティブのメインインターフェースとなり、同期APIは内部的な互換性層になります。既存の同期呼び出しには変更は必要ありません。カスタムストレージバックエンドは a 接頭辞付きの非同期メソッドに移行する必要があります（同期版の抽象メソッドは削除されました）。
  • Core/storage がパッケージに変更：SQLite は Core/storage/sqlite.py に移動し、MySQL / PostgreSQL が予め用意されています。StorageManager は互換性のエイリアスとして残ります。
  • 2.8.0：sdk.reload_plugin は sdk.reload_module に名前が変更されました。独立したイベントアクセス制御システム Core/access.py は scope.identity に統合されました（設定セクション ErisPulse.access は削除され、ErisPulse.scope.identity に移動しました）。コマンド ACL の独立した設定セクションは event.command.acl に統合されました。bind 系のスコープ API は辞書形式の設定に統合されました。
  • 削除：インストールスクリプトの root/管理者による強制確認

2.8.0 → 2.9.0

破壊的変更はなく、すべて宣言的な増分です。影モジュールの RuntimeError / ValueError をキャッチするコードは、2.9.0 の注意事項に従って調整する必要があります。

2.9.0 → 2.10.0

  • 設定書き込みエンジンを tomlkit から tomlclass に変更（依存関係ゼロ、TOML の損失のない編集）：コメント/キーの順序/空行の意味が保持される——config.toml を tomlkit を使って操作する外部ツールチェーンは移行が必要
  • uvicorn を >=0.35.0,<1.0 に固定（能力検出 Server._serve()、不足時は公開 serve() に降格）
  • 2.10.0：epsdk init / create テンプレートから enabled 設定フィールドを削除——モジュールの起動/停止はフレームワークが統一して管理し、ConfigClass は業務パラメータのみを保持する

2.10.x → 2.11.0

  • sdk.restart() の意味のアップグレード：コンポーネントレベルのホットリロード（モジュールホットリロードパイプライン + アダプタのコードレベルリロード）に変更。フレームワークの自動更新や entry-point の追加・削除の場合は hard_restart() を使用する。
  • インスタンスロックは .erispulse/config.lock に移行。旧ロックファイル（config/config.lock）を削除するデプロイメントでは、パスの同期も行う必要がある。

2.11.0 → 2.11.2

  • AccountConfigClass のアダプターが default アカウントテンプレートを自動生成しなくなりました。アカウントはユーザーがダッシュボードのアカウントウィザードで作成するようになります。"起動時に default アカウントが存在すること"に依存するデプロイメントは、明示的に追加する必要があります。
  • reload() / restart() の動作が厳格化されました（排他性と結合）。通常の使用には透明です。

2.11.x → 2.12.0

① ストレージの書き込み失敗の意味の厳格化（破壊的）：書き込み操作が失敗した場合（書き込みロックの競合タイムアウト / SQLエラー / 制約違反）は、StorageOperationError をスローするようになります（aset / adelete / aclear / set_multi および同期ブリッジ set / delete は同じパス）。以前のように False を返すことはなくなります。接続レベルで利用できない状態の冷却期間は、以前と同様に即座に失敗（False / None）します。

# 旧：戻り値で書き込み失敗を判断
if not storage.set("key", "value"):
    ...

# 新：try/except
try:
    storage.set("key", "value")
except StorageOperationError:
    ...

② run_main_loop が利用可能なメインループがない場合は、キューに登録して None を返すようになります。以前のように一時的なイベントループを作成することはなくなります。一時的なイベントループに依存している呼び出し元は、spawn_background を使用して既に登録されたメインループにスケジュールするように変更する必要があります。

③ コンテナ内での epsdk restart は、プロセス内でソフトリスタートをトリガーする SIGUSR1 を送信するように変更されます。プロセスの終了と再起動は行われなくなります。コンテナのデプロイでは、restart ポリシーを確認してください（プロセス全体のリスタートはコンテナに任せるべきです）。

④ 依存関係のアップグレード：tomlclass >=0.4.0,<0.5。

⑤ 2.12.0 / 2.12.1 でのデフォルト動作の変更：

  • ループ接続の自己修復：接続レベルで破損が検出された場合、自動的にキャッシュ接続を再構築します（2.12.0）。
  • コンポーネントの発見はデフォルトで有効になり、reload() / restart() の事前チェックが厳しくなります（2.11 系列）。
  • 2.12.1：イベントの冪等性の重複除去キーにプラットフォームの次元が追加され、ハンドラのマッチングが統一されます（detail_type 条件を宣言したハンドラは、イベントにその次元がない場合に透過しなくなり、ネイティブイベントのパスは引き続き許可されます）。セッションバインディングは detail_type: というプレフィックスキーもサポートします。

2.12.1（パッチ）

移行操作はありません。すべてがバグ修正および内部改善です。デフォルト動作の変更：ログファイル出力がデフォルトで有効（log_dir のデフォルトは "logs" で、logs/erispulse.log を書き込み、size/date ローテーションによる上限付き）——ファイルログを必要としないデプロイでは [ErisPulse.logger] log_dir = "" を設定してください。明示的に無効化（有効から無効に切り替える）すると、ファイルハンドラが自動的にクリーンアップされ、書き込みが残存することはありません。

一般的アドバイス

  • アップグレードする前に、対応するバージョンの CHANGELOG「注意事項」を確認してください。パッチバージョン（x.y.Z）は安心してアップグレードできます。
  • 重要なストレージへの書き込み操作は常に try/except を使用してください（バージョンに関係なく、良い実践方法です）。
  • カスタムバックエンド / 深度統合を行う方は、minor バージョンの「変更 / 削除」の分類に注意してください。

次のステップ

  • 変更の詳細について → ストレージバックエンド · 設定ファイルの説明
  • アップグレード後の動作が期待通りでない場合 → よくある質問 · ep doctor
  • 各バージョンの詳細な変更履歴 → CHANGELOG
