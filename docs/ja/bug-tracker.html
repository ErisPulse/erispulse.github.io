バグトラッカー

このドキュメントは、ErisPulse SDK の既知のバグとその修正状況を記録したものです。修正されたバージョンの日付順に並べられています。

読者の皆様へ どんなソフトウェアにも完璧さは存在せず、どんなに注意深く開発しても小さな間違いが残ります。本トラッカーに記録されているのは、実行に実際に影響を与える問題のみです。あまりにも些細で「軽度」のレベルにも達しないような欠陥は、ここには含まれません。リストに「重大」の項目が多めに見えるかもしれませんが、公開されている目的は、トラブルシューティングと再現をスムーズにすることであり、不安を煽ることではありません。目にする、記録する、修正する問題こそが、プロジェクトが常に良くなっている証拠です。このリストを見て不安になる必要はありません。これはトラブルシューティングのためのツールであり、恐怖の原因ではありません。

問題: ストレージを明示的に閉じる（または sdk.uninit() を呼び出す）ことなく終了するプロセス—独立したスクリプト、Ctrl+C で中断された後の終了、テストプロセス—は、業務コードが実行された後に終了せず、解釈器の終了段階で永久に停止します；Windows / Linux で再現します。 原因: CPython の終了は threading._shutdown()（すべての非 daemon スレッドを join する）を実行してから atexit コールバックを実行します。aiosqlite 0.22 以降、接続ワークスレッドは daemon=True を持たなくなり、ストレージの閉じるハックと受信箱の終了バッファ書き込みは atexit に登録されています—接続ワークスレッドは閉じるのを待つ、閉じるは join 終了を待つ、相互待ち。 影響バージョン: aiosqlite ≥ 0.22 に依存するすべてのバージョン（aiosqlite>=0.20.0 に上限なし、デフォルトの SQLite 後端は必発生） 修正バージョン: 2.12.1-dev.1 修正内容: ストレージ層に、スレッドの回収の前に実行する終了ハックのシーケンスを追加します（threading._register_atexit で登録）：ストレージに依存する終了バッファ書き込み（受信箱バッファ）→ 同期的にすべての生きている接続のワークスレッドを停止（イベントループを経由しない）→ ブリッジループを停止。同期ブリッジの有界待機の意味も収束します：タイムアウト後に書き込み操作はキャンセルされない（バックグラウンドで完了し、事後の失敗警告）、トランザクションの終了は必ず達成される、トランザクションの開始タイムアウトは StorageOperationError を投げる—以前のキューにあった書き込みはキャンセルされて破棄され、トランザクションの終了がキャンセルされると、接続と書き込みロックは解放されないままになります。 修正日: 2026/11/25 回帰テスト: tests/unit/test_unit_storage.py::TestStorageExitHooks（ハックの順序 / 単一ステップの失敗がブロックしない / 登録チャネル / SQLite 接続はイベントループを経由しないで停止）、::TestSyncBridgeTimeoutSemantics（書き込みは失敗しない / 事後の失敗は記録される / 開始タイムアウトでエラー / 終了は必ず達成）
