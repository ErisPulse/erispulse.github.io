ErisPulse.Core.module 模块

模块概述

ErisPulse 模块系统

提供标准化的模块注册、加载和管理功能，与适配器系统保持一致的设计模式

类列表

class ModuleManager(ManagerBase)

模块管理器

提供标准化的模块注册、加载和管理功能，模仿适配器管理器的模式

提示

  1. 使用register方法注册模块类
  2. 使用load/unload方法加载/卸载模块
  3. 通过get方法获取模块实例

async unload(name: str | None = None, *, module_name: str | None = None, purge: bool = False, reason: str = 'unload') -> bool

卸载指定模块或所有模块

卸载被其它模块依赖的模块时，依赖它的模块会级联卸载 （依赖者先卸载，日志说明级联链），避免依赖者持有失效引用继续运行。

purge 控制是否一并删除注册存根：

  • purge=False（默认）：只取消加载——卸载实例与资源，但保留 注册存根（模块类与元信息），模块仍可被 discover 重新发现、load() 重新实例化，无需重新 register()
  • purge=True：彻底卸载——同时删除注册存根（释放模块类引用）， 并对插件文件夹来源的模块清理 sys.modules，使插件及其独占依赖 可被 GC 回收（解决 NoneBot 式卸载后插件与依赖内存不释放的问题）； 级联卸载的依赖者同样被 purge。卸载后重新加载需重新 register()

卸载与热重载共用全局互斥：与进行中的 reload / restart / 归眠串行 （消除外部卸载与重载交叉导致的双重 on_unload）；等待上限 UNLOAD_LOCK_WAIT_TIMEOUT_SECS 秒，超时降级直接执行并留痕 （持锁重载卡死的极端场景不阻塞调用方）。

  • name: 模块名称，None表示卸载所有模块（默认None）

  • module_name (已弃用): 兼容旧关键字参数，等同 name

  • purge: 是否一并删除注册存根并清理 sys.modules（默认 False）

  • reason: 卸载来意标注，透传给 on_before_unload 钩子与

       ``module.before_unload`` 事件（``"unload"`` / ``"reload"`` /
   ``"disable"`` / ``"cascade"``；框架内部使用，常规调用保持默认）

返回值: 是否卸载成功

示例:

await module.unload("MyModule")  # 卸载单个模块（依赖者级联卸载）
await module.unload("MyModule", purge=True)  # 彻底卸载（释放类引用）
await module.unload()  # 卸载所有模块
async _unload_locked(name: str | None, *, purge: bool = False, reason: str = 'unload') -> bool

内部方法 unload 的实现体（调用方已持有热重载互斥锁，或已限时降级）

  • name: 模块名称，None 表示卸载所有模块
  • purge: 是否一并删除注册存根并清理 sys.modules
  • reason: 卸载来意标注

返回值: 是否卸载成功

async sleep(name: str | None = None, *, module_name: str | None = None) -> bool

归眠指定模块（懒加载休眠）

与 unload 的差异：释放运行时资源（on_unload / 归属任务 / 连接 / 注册资源），但保留懒加载代理与注册存根——模块回到"已注册未 加载"状态（与从未激活不可区分），下次属性访问 / module.call / activate_on 事件将透明唤醒（重新实例化并 on_load）。

归眠前触发 on_before_unload（reason="dormant"），模块可借 此把状态保存到 storage，唤醒后在 on_load 中恢复。自动归眠需在 加载策略中声明 get_load_strategy(dormant_after="30m")；任何已 加载模块均可手动归眠。

  • name: 模块名称
  • module_name (已弃用): 兼容旧关键字参数，等同 name

返回值: 是否归眠成功（未加载/未注册返回 True——无事可做）

示例:

await module.sleep("HeavyTool")   # 闲置归眠，释放资源
touch_activity(module_name: str) -> None

内部方法 记录模块活跃时间戳（休眠清扫判定用）

埋点位置：事件处理器调用（Core/Event/base._invoke_handler）、 命令执行（Core/Event/command）、module.call 目标解析。

  • module_name: 模块注册名
_ensure_dormancy_sweeper() -> None

内部方法 确保休眠清扫器后台循环已启动（幂等；无休眠声明时不启动）

async _dormancy_sweep_loop() -> None

内部方法 休眠清扫循环：按固定间隔扫描已加载且声明 dormant_after 的模块， 闲置超阈值即自动归眠（uninit 时随后台任务统一取消）

async _dormancy_sweep() -> None

内部方法 单轮休眠扫描：对闲置超过阈值的已加载模块自动归眠

依赖方策略：不级联、不跳过——懒模块的依赖方经由持久代理 （sdk.<Name>）/ module.call 访问，归眠后与"从未激活"不可 区分，唤醒路径照常生效。

async reload(name: str, *, full: bool = True) -> bool

热重载单个模块（支持任意来源：本地插件 / 运行时注册 / PyPI 安装包）

经模块加载器完整执行 语法预检 → 卸载旧实例 → 清理注册与 sys.modules 缓存（按顶层包名 + invalidate_caches，默认全量） → 重新发现/导入 → 重新注册并加载 流程；依赖该模块的模块会级联 重载并默认重导代码。本地插件（plugins/ 目录）来源重扫描插件 目录；运行时注册来源按定义模块重导并按类名重取；PyPI 安装包来源 重新查询 entry-point 并重导入模块代码（pip 升级后调用即可生效）。

full=False 切换为轻量重载：仅按元数据清理 sys.modules， PyPI 依赖者卸载后直接重新实例化——仅供超大依赖树的性能敏感场景。

  • name: 模块名（entry-point 名称、插件名或运行时注册名）
  • full: 是否全量重载（默认 True；False 为轻量逃生门）

返回值: 是否重载成功（SDK 未初始化时返回 False）

示例:

await sdk.module.reload("dice")      # 本地插件
await sdk.module.reload("MyRuntime") # 运行时注册模块

services(module_name: str | None = None) -> 'dict[str, list[dict[str, Any]]]'

服务目录：列出模块通过 get_meta().services 声明的对外服务

仅包含显式声明的模块（未声明的模块不出现在结果中）； 每个服务附带方法签名字符串、介绍文本与参数提示：

  • 介绍来源：services 中 {"name", "description"} 的显式声明

    （支持 i18n 字典，解析为当前语言）> 方法 docstring 首行 > 空串

  • 签名：inspect.signature 提取

  • 参数提示：parameters 中 {参数名: 说明} 显式声明

    （支持 i18n 字典）与方法 docstring :param: 行按参数合并， 单参数内显式声明优先；仅含签名内实际存在的参数

懒加载（已注册未加载）模块同样进入目录——服务发现先于加载发生， 调用方可据此决定是否 call() 唤醒目标模块。

为后续 MCP 化（调用点暴露给 AI）与生态服务发现提供数据基础。

  • module_name: 仅查询指定模块；None 时列出全部已注册模块中声明了服务的

返回值: {模块名: [{"name", "signature", "description", "parameters"}]}

           'description': '查询会话历史',
           'parameters': {'session_id': '会话 ID', 'n': '返回条数'}}]}
sdk.module.services("Chat")
{'Chat': [{'name': 'get_history', ...}]}

async call(module_name: str, method: str, *args: Any, timeout: float | None = None, **kwargs: Any) -> Any

跨模块调用目标模块的服务方法（协议化 RPC）

与 module.<Name>.<method>() 裸属性访问的差异： 目标模块未注册 / 未启用时抛出类型化异常而非 AttributeError； 懒加载模块自动唤醒；get_meta().services 契约白名单校验； 调用方经过 scope 出站维度（actions.<caller>.call）审计； 被调方法执行期间 current_owner 归因到目标模块， 其内部的 wait_reply / 出站发送 / 日志等正确归属； 调用方身份保留在 current_caller 上下文中（get_current_caller() 读取），供被调方识别调用来源； 协程方法带超时语义（超时抛 :class:ModuleCallTimeoutError）。

  • module_name: 目标模块名
  • method: 目标方法名
  • args: 位置参数（透传给目标方法）
  • timeout: 超时秒数（默认 30 秒；None 表示不限时；仅对协程方法生效）
  • kwargs: 关键字参数（透传给目标方法）

返回值: 目标方法的返回值

异常: ModuleNotAvailableError - 目标模块未注册 / 未启用 / 唤醒失败

异常: ServiceNotProvidedError - 方法不在目标模块的 services 白名单内（或为私有方法 / 不存在）

异常: ModuleCallError - 调用方被 scope 出站规则拒绝

异常: ModuleCallTimeoutError - 协程方法超时

示例:

result = await sdk.module.call("Chat", "get_history", session_id, n=20)

提示 服务方在 get_meta().services 声明契约收紧调用面（缺省时公开方法全开放）:

        return ModuleMeta(services=["get_history", "translate"])
