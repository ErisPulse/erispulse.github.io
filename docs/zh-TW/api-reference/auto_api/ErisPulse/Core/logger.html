ErisPulse.Core.logger 模块

模块概述

ErisPulse 日志系统

提供模块化日志记录功能，支持多级日志、模块过滤和内存存储。

提示

  1. 支持按模块设置不同日志级别
  2. 日志可存储在内存中供后续分析
  3. 自动识别调用模块名称

函数列表

内部方法

返回值: 带日期时间、级别且单行化的 Formatter

_format_message(msg: object, args: tuple) -> str

将日志消息与位置参数按 % 风格格式化

有 args 时应用 str(msg) % args，无 args 时保持原文不变（%s 字面量保留）， 格式化失败时回退到原始字符串。控制台路径仍由 Python logging 自行格式化， 此处仅为内存副本 / 订阅器提供与之一致的文本。

内部方法

  • msg: 原始日志消息
  • args: 位置参数元组

返回值: 格式化后的日志文本

_to_single_line(msg: str) -> str

将日志消息规范化为单行

统一 CRLF / CR 为 LF 后，把真实换行转义为字面 \n。多行消息 （异常堆栈文本、多行 f-string 等）若原样进入内存 / 订阅器 / plain 日志文件，会破坏"一行一记录"的日志纪律，并导致按行渲染的 消费端（Dashboard 表格、日志采集管道）出现空消息与错位。

内部方法

  • msg: 原始日志文本

返回值: 不含真实换行符的单行文本

class _SingleLineFormatter(logging.Formatter)

单行化文件格式化器

在标准格式化结果上把真实换行转义为字面 \n，保证日志文件 一行一记录。控制台（Rich/Stream）不受影响——多行消息在终端中 保持原始布局（如路由服务器的地址树）。

class _MemoryLogRecord

内存日志记录（__slots__ 紧凑存储）

替代旧实现的每条 5 键 dict（约 728B/条）：__slots__ 记录类去掉 实例字典与键哈希表，显著降低常驻内存日志副本的占用。字段与旧 dict 键一致（timestamp / level / level_num / module / message）。

对外消费点（get_logs / iter_logs / 订阅器补发）经 :meth:as_dict 转回 dict 形态，外部 API 形状不变；保留 __getitem__ 下标访问以兼容 存量内部消费点（如测试）的 dict 风格读取。

class Logger

日志管理器

提供模块化日志记录和存储功能

提示

  1. 使用set_module_level设置模块日志级别
  2. 使用get_logs获取历史日志
  3. 支持标准日志级别(DEBUG, INFO等)

方法列表

handler(handler_id: str = '', *, min_level: str = 'TRACE', owner: str | None = None) -> Callable

日志订阅装饰器

订阅器的 min_level 可低于全局日志级别，从而显式订阅 DEBUG / TRACE 等低级别日志。此时低级别日志仅推送给匹配的订阅器，不会输出到控制台， 也不会写入内存（历史补发仍受全局 memory_limit 限制）。

订阅在注册时归属到当前 owner（模块名/平台名），模块卸载时由框架 统一注销；也可用 owner 参数显式指定。

@sdk.logger.handler("dashboard", min_level="INFO")
def on_log(log_data: dict): ...

# 显式订阅低于全局级别的日志（如全局为 INFO，仍可收到 DEBUG）
@sdk.logger.handler("debug-tracer", min_level="DEBUG")
def on_debug(log_data: dict): ...

sdk.logger.handler("dashboard", min_level="INFO")(on_log)
  • handler_id: 订阅器唯一标识，为空时使用函数名
  • min_level: 最低日志级别
  • owner: 显式指定归属者；缺省时从当前 owner 上下文捕获
_register_handler(handler_id: str, callback: Callable[[dict], None], min_level: str, *, owner: str | None = None) -> None

unregister_by_owner(owner: str) -> int

注销指定归属者的全部日志订阅器，并回收其内存日志与模块级别

模块卸载 / 适配器关闭链经归属权门面（ownership.reclaim_sync） 自动调用；订阅回调通常持有模块实例，不注销会导致已卸载模块 无法被 GC 且持续接收全量日志。同时清理该归属者的内存日志队列 （_logs[模块名] 及 模块名.* 子级）与模块级别覆盖 （_module_levels），防止已卸载模块的日志残留长期驻留内存。

  • owner: 归属者（模块名 / 平台名）

返回值 (int): 注销的订阅器数量

set_memory_limit(limit: int) -> bool

设置单模块日志内存存储上限

  • limit: 单模块日志存储上限；0 表示关闭内存日志副本

    （不再写入任何内存日志，已有记录保留但不再增长），负数无效

返回值 (bool): 设置是否成功

set_total_memory_limit(limit: int) -> bool

设置全部模块内存日志的总条数上限

超限时按轮转策略淘汰最旧记录：从当前条数最多的模块队列头部 popleft。与单模块 :meth:set_memory_limit 独立生效——两者 任一触发都会淘汰记录。

  • limit: 全局总条数上限；0 表示不限，负数无效

返回值 (bool): 设置是否成功

示例:

logger.set_total_memory_limit(5000)  # 全局最多保留 5000 条
logger.set_total_memory_limit(0)     # 不限制总数

set_excluded_levels(levels: list[str]) -> bool

设置被屏蔽的日志等级列表

被屏蔽等级的日志将被完全丢弃：不写入内存、不推送给订阅器、 不输出控制台、不写入日志文件。常用于隐私保护场景， 例如 exclude_levels = ["EVENT"] 可隐藏消息收发内容 （消息收发日志使用 EVENT 等级记录）。

  • levels: 日志等级名称列表（如 ["EVENT", "DEBUG"]），空列表表示不屏蔽

返回值 (bool): 设置是否成功（含非法等级时返回 False 且不生效）

示例:

# 屏蔽 EVENT 等级（隐藏消息收发内容）
logger.set_excluded_levels(["EVENT"])
# 恢复所有等级
logger.set_excluded_levels([])

set_output_dir(directory: str, *, filename: str = 'erispulse.log', rotation: str = DEFAULT_LOG_ROTATION, max_size_mb: float = DEFAULT_LOG_MAX_SIZE_MB, backup_count: int = DEFAULT_LOG_BACKUP_COUNT, when: str = DEFAULT_LOG_ROTATION_WHEN) -> bool

设置日志输出目录（支持自动分段/轮转）

目录不存在时自动创建。与 set_output_file 互斥，调用后 会替换已有的文件日志输出。

  • directory: 日志目录路径（自动创建）
  • filename: 目录内的日志文件名（默认 "erispulse.log"）
  • rotation: 分段方式："size"（按大小，默认）/ "date"（按时间）/ "none"（不分段）
  • max_size_mb (size): 模式下单文件大小上限（MB，默认 10）
  • backup_count: 保留的历史日志文件数（默认 5，超出的最旧备份自动删除）
  • when (date): 模式轮转周期（"S"/"M"/"H"/"D"/"midnight"，默认每天零点）

返回值 (bool): 设置是否成功

示例:

# 在 config.toml 中配置（推荐）
[ErisPulse.logger]
log_dir = "logs"
log_rotation = "size"        # 按大小分段
log_max_size_mb = 10
log_backup_count = 5

# 或代码中动态设置：每天零点轮转，保留 7 份
logger.set_output_dir("logs", rotation="date", backup_count=7)
