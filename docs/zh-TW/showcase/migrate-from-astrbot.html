遷移指南：從 AstrBot 到 ErisPulse

Tip

什麼時候需要讀這篇：當你已有一個 AstrBot 機器人，想把它遷到 ErisPulse 時讀這篇。全新搭建請直接看快速開始。

先說結論：平台接入、模型、人格、知識庫都能搬；AstrBot 外掛不能搬——兩邊外掛 API 完全不同，外掛需要按 ErisPulse 模組規範重寫。資料不會自動遷移。

概念對照

AstrBot 裡的 ErisPulse 裡的 說明
平台適配器（QQ/微信/Telegram…） 平台適配器 概念一致，裝 ErisPulse 對應適配器即可
LLM Provider（API Key、模型） QvQChat 模型池 都是 OpenAI 相容接入；QvQChat 支援模型池自癒與難度路由
人格 Persona QvQChat 人格系統 系統提示詞 + 開場白 + 工具白名單，手工搬運
知識庫 QvQChat 知識庫 世界書式關鍵詞觸發 + 向量檢索，需重新匯入
WebUI Dashboard 模組啟停、配置、日誌、事件監控；QvQChat 另有獨立控制台
插件 模組 API 不同，需重寫（見下）
管理員/白名單 三維作用域 + 模組自身權限（如 QvQChat admins） 權限模型更細，逐模組配置

遷移步驟

  1. 搭框架：按快速開始初始化專案（Docker 或 pip 均可），裝上 Dashboard
  2. 接平台：epsdk install 你原來使用的平台適配器（QQ 生態裝 OneBot 適配器，Telegram 裝 Telegram 適配器……），登入方式與協定實作的選擇和 AstrBot 時期相同
  3. 裝智慧型代理：epsdk install ErisPulse-QvQChat，在模型池裡填入原來的 Base URL / API Key / 模型名稱
  4. 搬遷人格與知識庫：人格到 QvQChat 人格頁逐條新建；知識庫文件重新匯入
  5. 重寫外掛：按下一節對照，把原外掛的「命令 → 處理邏輯」翻譯成 ErisPulse 模組

外掛重寫對照

同一個「收到 /ping 回 pong」的外掛，兩邊的寫法：

AstrBot 外掛（示意，以 AstrBot 文件為準）：

from astrbot.api.event import filter, AstrMessageEvent

@filter.command("ping")
async def ping(self, event: AstrMessageEvent):
    yield event.plain_result("pong")

ErisPulse 模組（完整可執行，見模組開發入門）：

from ErisPulse.Core.Event import command

@command("ping", help="測試機器人是否在線")
async def ping_handler(event):
    await event.reply("pong")

差異要點：

  • 事件模型：AstrBot 每個平台各自的事件物件；ErisPulse 是 OneBot12 統一事件，event.reply / SendDSL 在所有平台行為一致
  • 套件結構：ErisPulse 模組是標準 Python 套件，用 epsdk create module 腳手架產生，發佈到 PyPI + 模組市場
  • 定時任務 / 儲存：安裝 Cron 模組或直接用框架內建儲存 API，不引入第三方依賴

建議的遷移策略

並行雙跑：ErisPulse 機器人先接一個測試群跑通全部功能，確認無缺失後再切主群。兩邊平台帳號體系獨立（各自的協議實現/Token），互不干擾，回退成本低。

Note

AstrBot 的插件 API 與功能清單持續演進，本頁對照以通用概念為主；具體某個插件能否找到 ErisPulse 等價物，先到模組市場搜一下，沒有就照上節重寫——多數業務插件在 ErisPulse 裡的實現反而更短。
