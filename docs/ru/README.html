Документация ErisPulse

ErisPulse — это фреймворк для асинхронных модульных роботов, основанный на событийном подходе: бизнес-код пишется один раз, а адаптеры позволяют развернуть робота на QQ, Telegram, Kook, Yunhu и других платформах. Встроенные плагины, горячая перезагрузка и полный набор инструментов для разработки — всё это работает из коробки.

Впервые используете? Начните с 5-минутного краткого руководства — от установки до запуска первого робота, всё покрыто.

Выберите свой путь

В зависимости от ваших целей, выберите соответствующий учебный путь. Каждый путь организован от простого к сложному.

Important

Не нужно читать всю документацию. Большинству разработчиков достаточно прочитать 5 основных статей уровня L1 (около 1–2 часов), чтобы самостоятельно реализовать 90% функциональности; остальные статьи предназначены для конкретных сценариев — читайте по мере необходимости. В начале каждой статьи указано, когда она может понадобиться.

L1: Основные пять статей: Введение в разработку модулей → Основные понятия → Обёртка событий → Описание конфигурационного файла → Обработка исключений

Для авторов адаптеров дополнительно: Введение в разработку адаптеров → Конвертер событий → Подробное руководство по SendDSL

Общая таблица понятий

Когда неясно, какой подсистемой управляет какая задача, ориентируйтесь по этой таблице:

Подсистема Отвечает на вопрос Краткое правило
Коммуникация (module-communication) Как модули могут вызывать друг друга, как отправлять события? Для вызова между модулями используйте module.call; если другая сторона объявила meta.services, можно вызывать только методы из белого списка
Права доступа (scope) Кто может использовать модуль, кто может вызывать события, какие действия разрешены? Три контрольные точки — привязка модуля, допуск идентификации, ограничение исходящих действий, все регулируются пользовательскими настройками
Принадлежность (ownership) Что происходит с соединениями, таймерами, подписками после выгрузки модуля? Кто зарегистрировал, тот и владеет; при выгрузке ресурсы автоматически очищаются
Ленивая загрузка и сон (lazy-loading) Когда модуль загружается, и куда уходит, когда бездействует? Модуль активируется по событиям activate_on, переходит в сон по dormant_after
Взаимодействие (interaction) Как ждать следующего ответа пользователя, как реализовать многошаговый сбор? wait_reply ждёт одно сообщение, .got() цепочкой собирает несколько, сессионные локи гарантируют отсутствие конфликтов
Теневой запуск (shadow) Как можно протестировать новую версию модуля без влияния на основной поток? Теневой модуль получает копию сообщений, исходящие сообщения только записываются, promote переводит в основной поток только после ручного подтверждения
Хранилище (storage-backends) Где хранятся данные, как менять хранилище? Одна и та же API-обёртка, переключение между sqlite / mysql / postgres через конфигурацию

Способы разработки

ErisPulse поддерживает два способа разработки:

  • Разработка модулей (рекомендуется): создание отдельного пакета модуля, устанавливаемого через менеджер пакетов, удобно для распространения и управления.
  • Встраиваемая разработка: написание обработчиков прямо в проекте, подходит для быстрой разработки прототипов. Подробнее см. 5-минутное краткое руководство.
