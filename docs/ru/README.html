Документация ErisPulse

ErisPulse — это фреймворк асинхронного модульного робота, основанный на событиях — бизнес-код пишется один раз, а через адаптеры разворачивается на QQ, Telegram, Kook, Yunhu и других платформах. Система плагинов, горячая перезагрузка и полноценный инструментарий разработчика предоставляются из коробки.

Впервые используете? Просто посмотрите 5-минутное руководство — от установки до запуска первого робота, шаг за шагом.

Выберите свой путь

Выберите учебный путь в зависимости от ваших целей. Внутри каждого пути темы расположены от простого к сложному.

[!IMPORTANT] Не нужно читать все документы. Большинству разработчиков достаточно прочитать пять основных статей уровня L1 (около 1–2 часов), чтобы самостоятельно разрабатывать 90% функциональности; остальные документы — это справочная информация по конкретным сценариям — читайте по мере необходимости. В начале каждой статьи указано, когда нужно читать эту статью.

Пять основных статей уровня L1: Введение в разработку модулей → Основные понятия → Обёртка событий → Описание файла конфигурации → Обработка исключений

Авторам адаптеров дополнительно: Введение в разработку адаптеров → Конвертер событий → Подробное руководство по SendDSL

Группировка по сценариям (читайте по мере необходимости)

Группа Документ Проблемы, которые могут возникнуть, если не понимать первую статью
Запуск и управление Процесс запуска и ручное управление · Ленивая загрузка Не понимание цепочки запуска (Finder / Loader / Manager / Router), модуль может не загрузиться, и разработчик будет смотреть в логи, ничего не понимая
Коммуникация Взаимодействие между модулями · Пул подключений и бродкаст · Система маршрутизации Не понимание белого списка сервисов (meta.services), вызовы module.call между модулями будут отклоняться ошибкой ServiceNotProvidedError без объяснения
Хранение данных Хранилища данных · SQL-строитель · Сетевые клиенты Не понимание семантики кулдауна при сбоях подключения, при джиттере базы данных можно ошибочно решить, что фреймворк "сломался" (на самом деле операции с хранилищем быстро завершаются с ошибкой, а затем автоматически переподключаются)
Диалоги Многошаговые диалоги (Conversation) · Почтовый ящик сессий · MessageBuilder · Международизация Не понимание взаимоисключающих сессий, два модуля могут пересекать друг друга при ожидании ответа одного и того же пользователя
Производительность Бенчмарки и оптимизация производительности Не проверяя бенчмарки перед развертыванием, планирование мощности будет основано на догадках; не сравнивая результаты после обновления, невозможно обнаружить падение производительности
Серый деплой Серый модуль и серый деплой Не понимание пяти уровней изоляции, ранняя активация серого модуля приведёт к тому, что исходящие сообщения серого модуля попадут к реальным пользователям

Таблица отношений между подсистемами

Когда неясно, какая подсистема отвечает за что, смотрите в эту таблицу:

Подсистема Отвечает на вопрос Односложный мемориал
Коммуникация (module-communication) Как модули могут вызывать друг друга, как отправлять события в определённый модуль? Для взаимодействия между модулями используйте module.call; если другой модуль объявил meta.services, можно вызывать только методы из белого списка
Права доступа (scope) Кто может использовать этот модуль, кто может запускать события, какие действия можно выполнять? Три шлагбаума — привязка модуля, допуск по идентичности, ограничение исходящих действий, всё определяется конфигурацией пользователя
Принадлежность (ownership) Что происходит с подключениями, таймерами, подписками после выгрузки модуля? Всё, что зарегистрировано, принадлежит, при выгрузке всё автоматически очищается, без висящих ресурсов
Ленивая загрузка и сон (lazy-loading) Когда модуль загружается, и куда он уходит в состоянии бездействия? activate_on — модуль активируется при необходимости, dormant_after — модуль уходит в спящий режим при бездействии
Интерактивность (interaction) Как ожидать следующего ответа пользователя, как писать многошаговые сборы? wait_reply — ожидание одного сообщения, .got() — цепочка сбора нескольких сообщений, сессионные аренды гарантируют отсутствие конфликтов
Серый деплой (shadow) Как можно протестировать новый модуль, не влияя на рабочую версию? Серый модуль получает копии данных, исходящие сообщения записываются, но не отправляются реальным пользователям, promote — активация по решению человека
Хранилище (storage-backends) Где хранятся данные, как можно менять хранилище? Один и тот же API хранения, переключение между sqlite / mysql / postgres производится через конфигурацию

Способы разработки

ErisPulse поддерживает два способа разработки:

  • Разработка модулей (рекомендуется): создание отдельного пакета модуля, установка через менеджер пакетов, удобно для распространения и управления.
  • Встраиваемая разработка: непосредственное написание обработчиков в проекте, подходит для быстрой разработки прототипа. Подробнее см. 5-минутное руководство.

  • Поддержка разработки с помощью ИИ — получение подсказок для ИИ-ассистентов программирования
