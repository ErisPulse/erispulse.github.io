Стандарт спецификации возвращаемых значений адаптеров ErisPulse

Tip

Когда читать этот документ: когда вы реализуете возвращаемые значения call_api / Send / Request в адаптере и хотите убедиться, что структура ответа и коды возврата соответствуют стандарту ErisPulse, или вам нужно выяснить значение конкретного retcode — сверяйтесь с этим документом. Если в этом нет необходимости — пропустите.

1. Описание

Откуда взялась эта спецификация?

Для обеспечения единообразия возвращаемых значений интерфейсов отправки на различных платформах и совместимости с OneBot12 адаптеры ErisPulse для формата API-ответов используют стандарт структуры возвращаемых значений отправки сообщений, определённый в OneBot12.

Однако протокол ErisPulse имеет некоторые особые определения:

    1. Среди базовых полей message_id является обязательным, но в стандарте OneBot12 такого поля нет
    1. В возвращаемое содержимое необходимо добавить поле {platform_name}_raw для хранения исходных данных ответа

2. Базовая структура возвращаемого значения

Все ответы на действия должны содержать следующие базовые поля:

Имя поля Тип данных Обязательное Описание
status string Да Статус выполнения, должен быть "ok" или "failed"
retcode int64 Да Код возврата, следует правилам кодов возврата OneBot12
data any Да Данные ответа; при успехе содержит результат запроса, при неудаче — null
message_id string Да Идентификатор сообщения; если отсутствует — пустая строка
message string Да Сообщение об ошибке; при успехе — пустая строка
{platform_name}_raw any Нет Исходные данные ответа

Необязательные поля:

Имя поля Тип данных Обязательное Описание
echo string Нет Если запрос содержит поле echo, оно возвращается в неизменном виде

3. Полная спецификация полей

3.1 Общие поля

Пример успешного ответа

{
    "status": "ok",
    "retcode": 0,
    "data": {
        "message_id": "1234",
        "time": 1632847927.599013
    },
    "message_id": "1234",
    "message": "",
    "echo": "1234",
    "telegram_raw": {...}
}

Пример ответа с ошибкой

{
    "status": "failed",
    "retcode": 10003,
    "data": null,
    "message_id": "",
    "message": "Отсутствует обязательный параметр: user_id",
    "echo": "1234",
    "telegram_raw": {...}
}

4. Требования к реализации

  1. Все ответы должны содержать поля status, retcode, data и message
  2. Если запрос содержит непустое поле echo, ответ должен содержать поле echo с тем же значением
  3. Коды возврата должны строго следовать спецификации OneBot12
  4. Сообщения об ошибках (message) должны быть понятны человеку

5. Расширения спецификации

ErisPulse сделал следующие расширения поверх стандартной структуры возвращаемых значений OneBot12:

5.1 Обязательное поле message_id

В стандарте OneBot12 message_id находится внутри объекта data и не является обязательным. ErisPulse поднял его до обязательного поля верхнего уровня:

  • Если message_id недоступен, следует установить пустую строку ""
  • message_id присутствует всегда, модулям не нужно выполнять проверку на null

5.2 Поле исходного ответа {platform}_raw

Возвращаемое значение должно содержать поле {platform}_raw, в котором хранится полная копия исходных данных ответа платформы:

{
    "status": "ok",
    "retcode": 0,
    "data": {"message_id": "1234", "time": 1632847927},
    "message_id": "1234",
    "message": "",
    "telegram_raw": {
        "ok": true,
        "result": {"message_id": 1234, "date": 1632847927, ...}
    }
}

Требования:

  • {platform}_raw должен быть глубокой копией исходного ответа, а не ссылкой
  • platform должен полностью совпадать с именем платформы, указанным при регистрации адаптера (с учётом регистра)
  • Информация об ошибках в исходном ответе также должна сохраняться для удобства отладки

5.3 Расширенные коды возврата фреймворка (пользовательские три младших разряда сегмента ошибок платформы 34xxx)

Спецификация OneBot12 позволяет реализациям определять собственные значения трёх младших разрядов 3xxxx. Семантика 34xxx — Platform Error (ошибка платформы бота, например сбой из-за ограничений платформы). Внутри 34xxx используется послойно по зонам ответственности:

Сегмент (младшие три разряда) Принадлежность Назначение
340xx Реализация адаптера Семейство операций запросов (Request Not Found / Already Handled / Not Supported / Permission Denied, см. request-action-spec §7)
341xx–345xx Реализация адаптера Ошибки на стороне платформы: права доступа / антифрод / ограничения аккаунта и т. п. (младшие три разряда определяются реализацией, исходная ошибка помещается в {platform}_raw)
346xx Фреймворк ErisPulse (зарезервировано) Перехваты самим фреймворком и общие сбои; адаптерам/модулям не занимать
347xx–349xx Реализация адаптера Прочие ошибки выполнения на стороне платформы

Коды 346xx, используемые в настоящее время фреймворком ErisPulse:

Код ошибки Название ошибки Описание
34600 SDK Failure Общий сбой фреймворка (код возврата по умолчанию для make_error())
34601 Action Denied Исходящее действие отключено скоупом (scope.actions); вызов не инициируется, сразу возвращается этот ответ

Разграничение ответственности: 34601 — это перехват фреймворком до вызова (модуль вообще не имеет права инициировать действие); коды платформы 34004 / 34xxx — это действие отправлено, но отклонено платформой (например, у бота нет прав, сработал антифрод). При диагностике проблем с правами модули должны проверять оба случая: сначала 34601 (свой модуль отключён скоупом), затем 34xxx (ограничения на стороне платформы).

Структура возврата — стандартный ответ с ошибкой из §2:

{
    "status": "failed",
    "retcode": 34601,
    "data": null,
    "message_id": "",
    "message": "action 'send' denied by scope.actions"
}

5.4 Контрольный список для реализации адаптера

  • Содержит поля status, retcode, data, message_id, message
  • Коды возврата следуют спецификации OneBot12 (подробнее см. §3.2)
  • message_id присутствует всегда (пустая строка, если недоступен)
  • {platform}_raw содержит исходные данные ответа платформы

6. Примечания

  • Для кодов ошибок 3xxxx три младших разряда могут определяться реализацией самостоятельно
  • Избегайте использования зарезервированных сегментов ошибок (4xxxx, 5xxxx)
  • 34600 / 34601 зарезервированы фреймворком ErisPulse (см. §5.3), адаптерам/модулям следует их не использовать
  • Сообщения об ошибках должны быть краткими и понятными для удобства отладки
