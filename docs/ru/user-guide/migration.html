Руководство по обновлению и миграции

Tip

Когда это нужно читать: перед обновлением со старой версии сверьте критические изменения, требующие правки кода или сверки развёртывания. Достаточно прочитать соответствующие разделы, начиная с вашей текущей версии; патч-версии (patch) никогда не содержат действий по миграции. Полный перечень изменений по каждой версии см. в CHANGELOG.

Дисциплина версий: патч-версии (x.y.Z) не содержат действий по миграции, изменения, требующие правки кода, появляются только в minor-версиях (x.Y.0); эта страница охватывает все критические изменения с 2.0.0 по настоящее время (2.5.0 — первая версия, готовая к эксплуатации; миграция 1.x → 2.0.0 описана в записи 2.0.0 CHANGELOG).

2.0.x → 2.5.0 (порог готовности к эксплуатации)

  • ⚠️ Строгий режим включён по умолчанию (уровень 1): старые компоненты, не наследующие BaseModule / BaseAdapter, по умолчанию отклоняются при загрузке — список исключений [ErisPulse.framework] strict_mode_exceptions.modules/adapters либо мягкий режим strict_mode = 0
  • Интерактивное подтверждение языка при первом запуске (пять языков i18n): для автоматизированных развёртываний язык нужно задать заранее (переменная окружения ERISPULSE_LANG или конфигурация)
  • Удалены сторонние зависимости с C-расширениями (watchdog / packaging) — улучшена совместимость установки на aarch64/ARM; развёртываниям с зафиксированными версиями в requirements нужна синхронная очистка

Критические изменения внутри серии 2.5.x

  • Управление алиасами CLI (2.5.5): удалён алиас ini (слишком близок к install), lr переименован в lsr — команды в скриптах развёртывания требуют синхронизации
  • Рефакторинг схемы конфигурации (2.5.5): универсальный базовый класс BaseConfig (AdapterConfig — алиас совместимости), поддержка формата i18n в description; алиас AccountConfig удалён — проверьте наследование пользовательских классов конфигурации
  • Рефакторинг доступа к конфигурации адаптера (2.5.5): self.cfg читается в реальном времени (self.config — алиас совместимости), кэширующие методы _load_config() / _load_accounts() удалены — адаптерам, вызывавшим эти приватные методы напрямую, следует перейти на self.cfg
  • Обнаружение компонентов включено по умолчанию (2.5.5): новые установленные компоненты по умолчанию получают enabled=true

2.6.x

  • Удалён весь пакет Core/web_status/, внешние изображения маскота и статическое монтирование /status-assets — развёртываниям, зависящим от этого маршрута, требуется миграция на Dashboard

2.7.x

  • Занятый порт — фатальная ошибка (2.7.1): синхронная предпроверка перед запуском, sdk.init() возвращает False, порт больше не сдвигается молча на следующий — скрипты развёртывания должны гарантировать свободный порт
  • Слой абстракции хранилища переведён на асинхронный нативный контракт (2.7.1): асинхронные интерфейсы (aget / aset / aExecute / atransaction) стали нативным основным интерфейсом, синхронный API стал встроенным слоем совместимости — существующие синхронные вызовы не требуют никаких правок; кастомные бэкенды хранилища обязаны мигрировать на асинхронные методы с префиксом a (синхронные версии абстрактных методов удалены)
  • Core/storage преобразован в пакет: SQLite перенесён в Core/storage/sqlite.py, MySQL / PostgreSQL предустановлены; за StorageManager сохранён алиас совместимости
  • 2.8.0: sdk.reload_plugin переименован в sdk.reload_module; отдельная система допуска событий Core/access.py объединена в scope.identity (секция конфигурации ErisPulse.access удалена, мигрирована в ErisPulse.scope.identity); отдельная секция конфигурации ACL команд объединена в event.command.acl; API скоупов семейства bind приведён к конфигурации в виде словаря
  • Удалено: принудительное подтверждение root/администратора в установочном скрипте

2.8.0 → 2.9.0

Критических изменений нет (все — декларативные дополнения); коду, перехватывающему RuntimeError / ValueError теневых модулей, нужна корректировка согласно примечаниям версии 2.9.0.

2.9.0 → 2.10.0

  • Движок записи конфигурации: tomlkit → tomlclass (редактирование TOML без потерь, ноль зависимостей): семантика сохранения комментариев/порядка ключей/пустых строк не изменилась — внешним инструментальным цепочкам, напрямую импортирующим tomlkit для работы с config.toml, нужна миграция
  • Для uvicorn зафиксирована зависимость >=0.35.0,<1.0 (обнаружение возможностей через Server._serve(), при отсутствии — откат к публичному serve())
  • 2.10.0: из шаблонов epsdk init / create удалено поле конфигурации enabled — включение/отключение модулей управляется централизованно фреймворком, ConfigClass несёт только бизнес-параметры

2.10.x → 2.11.0

  • Семантика sdk.restart() повышена до горячей перезагрузки на уровне компонентов (конвейер горячей перезагрузки модулей + перезагрузка кода адаптеров); для самообновления фреймворка и сценариев добавления/удаления entry-point используйте hard_restart()
  • Блокировка экземпляра перенесена в .erispulse/config.lock — развёртываниям со скриптами очистки старой блокировки (ранее config/config.lock) нужно синхронно обновить путь

2.11.0 → 2.11.2

  • Адаптеры, объявляющие AccountConfigClass, больше не генерируют автоматически шаблон аккаунта default — аккаунты теперь создаются пользователем в мастере аккаунтов Dashboard; развёртываниям, полагающимся на «аккаунт default сразу после запуска», нужно добавить его явно
  • Ужесточение поведения reload() / restart() (взаимное исключение и объединение) прозрачно для обычного использования

2.11.x → 2.12.0

① Семантика сбоев записи в хранилище ужесточена (критическое): сбой операции записи (таймаут конкуренции за блокировку записи / SQL-ошибка / конфликт ограничений) теперь приводит к выбросу StorageOperationError (aset / adelete / aclear / set_multi и синхронные мосты set / delete — тот же путь), молчаливое возвращение False исключено; быстрый отказ в период охлаждения при недоступности на уровне соединения (False / None) остался прежним.

# Старый вариант: определять сбой записи по возвращаемому значению
if not storage.set("key", "value"):
    ...

# Новый вариант: try/except
try:
    storage.set("key", "value")
except StorageOperationError:
    ...

② Когда у run_main_loop нет доступного основного цикла, он теперь ставит запрос в очередь и возвращает None, не создавая временный цикл событий — вызывающему коду, полагавшемуся на поведение временного цикла, следует перейти на spawn_background (планирование обратно в зарегистрированный основной цикл).

③ epsdk restart внутри контейнера теперь отправляет SIGUSR1, запуская мягкую перезагрузку внутри процесса, вместо завершения и повторного запуска — проверьте политику restart при контейнерном развёртывании (перезапуск всего процесса возложен на контейнер).

④ Повышение зависимостей: tomlclass >=0.4.0,<0.5.

⑤ Изменения поведения по умолчанию (2.12.0 / 2.12.1):

  • Самовосстановление соединений цикла: при обнаружении повреждения на уровне соединения кэшированное соединение пересоздаётся автоматически (2.12.0)
  • Обнаружение компонентов включено по умолчанию, ужесточены предпроверки reload() / restart() (серия 2.11)

2.12.1 (патч)

Действий по миграции нет. Всё — исправления дефектов и внутренние улучшения. Изменение поведения по умолчанию: вывод лога в файл включён по умолчанию (log_dir по умолчанию "logs", запись в logs/erispulse.log, ротация по размеру/дате с ограничением) — развёртываниям, которым не нужен файловый лог, следует установить [ErisPulse.logger] log_dir = ""; при явном отключении (переключении обратно из включённого состояния) файловый handler удаляется автоматически, записей не остаётся.

Общие рекомендации

  • Перед обновлением прочитайте раздел «Примечания» CHANGELOG соответствующей версии; патч-версии (x.y.Z) можно обновлять без опасений
  • Для важных записей в хранилище всегда используйте try/except (хорошая практика, не зависящая от семантики и версии)
  • Кастомные бэкенды / решения с глубокой интеграцией должны следить за категориями «Изменения / Удаления» в minor-версиях
