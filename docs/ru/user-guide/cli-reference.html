Справочник командной строки

Инструмент командной строки ErisPulse (epsdk) предоставляет функции управления проектами и пакетами.

Совет: Все команды можно подробно описать с помощью epsdk <команда> --help. Главная помощь epsdk (без команды) группирует по категориям: Проекты (init / create / run), Управление компонентами (install / uninstall / upgrade / list / list-remote / types), Конфигурация и диагностика (config / doctor / i18n), Прочее (self-update / version).

Команды управления пакетами

Команда Алиас Параметры Описание

[--upgrade/-U] [--pre] [-e ПУТЬ] [--user] [--no-deps] [-t КАТАЛОГ] [--index-url URL] [--extra-index-url URL] [--no-cache-dir] [-r ФАЙЛ] [-c ФАЙЛ] [--force-reinstall] [--ignore-installed] [--compile/--no-compile] [--prefix КАТАЛОГ] [--src КАТАЛОГ] [--config-settings НАСТРОЙКИ] [--no-binary ФОРМАТ] [--only-binary ФОРМАТ] [--prefer-binary] [--build-isolation/--no-build-isolation] [--upgrade-strategy {eager,only-if-needed,to-satisfy-only}] [--break-system-packages] [--no-uv] Установить модуль/адаптер

install

Установить пакет модуля или адаптера ErisPulse. Если имя пакета не указано, запускается интерактивный режим установки.

Алиас: i, add

Параметры:

Параметр Короткий Описание
[пакет]... Имя устанавливаемого пакета, можно указать несколько
--upgrade -U Обновить до последней версии при установке
--pre Разрешить установку предрелизных версий
--editable -e Установить в режиме редактирования (требуется указать путь)
--user Установить в каталог site-packages пользователя
--no-deps Не устанавливать зависимости
--target -t Установить в указанный каталог
--index-url Указать URL зеркала PyPI
--extra-index-url Дополнительный URL зеркала PyPI (можно указать несколько раз)
--no-cache-dir Отключить кэш
--requirement -r Установить из файла requirements
--constraint -c Установить из файла constraint
--force-reinstall Принудительно переустановить
--ignore-installed Игнорировать уже установленные пакеты
--compile Скомпилировать .pyc файлы после установки
--no-compile Не компилировать .pyc файлы после установки
--prefix Установить в указанный префикс каталога
--src Используемый каталог исходного кода для установки в режиме редактирования
--config-settings Передача настроек в сборочный бэкенд (можно указать несколько раз)
--no-binary Ограничение использования бинарных пакетов (формат :all:)
--only-binary Ограничение использования только бинарных пакетов (формат :all:)
--prefer-binary Предпочитать бинарные пакеты
--build-isolation Включить изоляцию сборки
--no-build-isolation Отключить изоляцию сборки
--upgrade-strategy Стратегия обновления: eager, only-if-needed, to-satisfy-only
--break-system-packages Разрешить изменение системных пакетов, управляемых системным менеджером
--no-uv Использовать pip вместо uv

Примеры:

# Установка одного модуля
epsdk install Weather

# Установка нескольких модулей
epsdk install Yunhu Weather

# Установка из зеркала и обновление
epsdk install Weather -U --index-url https://pypi.tuna.tsinghua.edu.cn/simple

# Установка в режиме редактирования (режим разработки)
epsdk install -e ./my-adapter

uninstall

Удалить установленный модуль или адаптер ErisPulse. Если имя пакета не указано, запускается интерактивный режим удаления.

Алиас: rm, remove

Параметры:

Параметр Описание
<пакет>... Имя удаляемого пакета, можно указать несколько
--no-uv Использовать pip вместо uv

Примеры:

# Удаление одного модуля
epsdk uninstall Weather

# Удаление нескольких модулей
epsdk uninstall Yunhu Weather

upgrade

Обновить установленные компоненты ErisPulse. Если имя пакета не указано, запускается интерактивное обновление всех.

Алиас: up

Параметры:

Параметр Короткий Описание
[пакет]... Имя пакета для обновления, можно указать несколько
--force -f Принудительное обновление, пропуск подтверждения
--pre Разрешить обновление до предрелизных версий
--no-uv Использовать pip вместо uv

Примеры:

# Обновление всех пакетов
epsdk upgrade

# Обновление указанного пакета
epsdk upgrade Weather

# Принудительное обновление (пропуск подтверждения)
epsdk upgrade -f

self-update

Обновить сам SDK ErisPulse до последней версии.

Алиас: su, update

Параметры:

Параметр Короткий Описание
[версия] Указание целевой версии для обновления
--pre Разрешить обновление до предрелизных версий
--force -f Принудительное обновление, пропуск подтверждения
--no-uv Использовать pip вместо uv

Примеры:

# Обновление до последней стабильной версии
epsdk self-update

# Обновление до указанной версии
epsdk self-update 1.2.3

# Разрешить предрелизные версии
epsdk self-update --pre

# Принудительное обновление
epsdk self-update -f

Note

При установке через uv tool install ErisPulse команда автоматически переходит на uv tool upgrade ErisPulse (при указании версии — uv tool install ErisPulse==<версия> --force), прямое обновление pip-ом удаляет инструмент из среды uv. При обновлении в Windows запуск происходит в новом окне консоли: текущий CLI должен завершиться, чтобы освободить файлы инструментальной среды, после завершения обновления перезапустите терминал.

Команды конфигурации

Команда Алиас Параметры Описание
config cfg, conf [имя] [--list/-l] [--json] Интерактивная настройка декларативных параметров адаптера/модуля

config

Интерактивно заполняет декларативные параметры конфигурации адаптера/модуля. Визуальный интерфейс генерируется на основе класса конфигурации (ConfigClass / AccountConfigClass), ввод проверяется, не нужно вручную писать config.toml.

Адаптеры дополнительно поддерживают управление несколькими аккаунтами (бот аккаунт): добавление/редактирование/удаление аккаунтов, а также включение/отключение переключателей.

Алиас: cfg, conf

Параметры:

Параметр Короткий Описание
[имя] Имя цели (название платформы адаптера или модуля), оставьте пустым для выбора
--list -l Вывести только статус конфигурации всех целей, не запуская визуальный интерфейс
--json Вывести статус конфигурации всех целей в формате JSON (для CI / скриптов), не запуская визуальный интерфейс

Примеры:

# Вывести статус конфигурации всех адаптеров/модулей
epsdk config --list

# Вывести статус конфигурации в формате JSON (для CI / скриптов)
epsdk config --json

# Интерактивный выбор цели для настройки
epsdk config

# Непосредственная настройка указанного адаптера
epsdk config yunhu

# Непосредственная настройка указанного модуля
epsdk config MyModule

Описание:

  • Статус конфигурации делится на четыре категории: Готово (валидация пройдена), Незавершено (отсутствуют обязательные поля или валидация не пройдена), Не настроено (никогда не генерировалось), Без конфигурации (цель не объявляет класс конфигурации)
  • Значения полей снабжены указанием источника: уже настроенные отображаются как （Текущее:значение）, не настроенные отображаются как （По умолчанию:значение）; просто нажатие Enter сохраняет это значение
  • Ввод секретных полей (объявленных как secret) не отображается, нажатие Enter сохраняет установленное значение
  • В режиме интерактивного выбора после завершения одного визуального интерфейса возвращается в меню выбора (статус обновляется), можно последовательно настроить несколько целей, нажатие Enter выходит
  • При неудачной валидации формы и отказе от повторного ввода, текущий визуальный интерфейс прерывается и никакая конфигурация не записывается (избегается состояние "включено, но конфигурация не завершена")
  • Сохранение немедленно записывается в config/config.toml, доступно в Dashboard и запущенному SDK; для применения новых настроек аккаунта в запущенном адаптере перезапустите процесс
  • epsdk install (интерактивная установка) и epsdk init после успешной установки адаптера, если обнаружено объявление конфигурации, автоматически запускают визуальный интерфейс; при установке по командной строке с указанием имени пакета выводится только подсказка о конфигурации

Команды управления запуском

Tip

epsdk run автоматически обнаруживает и использует виртуальное окружение .venv в каталоге проекта для запуска робота (также можно явно указать интерпретатор через переменную окружения ERISPULSE_PYTHON). epsdk install / uninstall / upgrade / list также действуют на виртуальное окружение проекта.

Команда Алиас Параметры Описание
run r [скрипт] [--reload] [--strict/--no-strict] Запуск указанного скрипта или SDK

run

Запуск скрипта проекта ErisPulse или прямой запуск SDK. Поддерживает режим горячей перезагрузки.

Алиас: r

Параметры:

Параметр Описание
[скрипт] Файл скрипта для запуска, если не указан, запускается SDK
--reload Включить режим горячей перезагрузки, автоматически перезапускать при изменении файлов
--strict / --no-strict Временно включить / отключить строгий режим (только для этого запуска, не записывается в конфигурацию); по умолчанию следует ErisPulse.framework.strict_mode

Примеры:

# Прямой запуск SDK
epsdk run

# Запуск указанного файла скрипта
epsdk run main.py

# Горячая перезагрузка (автоматический перезапуск при изменении файлов)
epsdk run main.py --reload

# Горячая перезагрузка SDK
epsdk run --reload

# Временный строгий режим: предварительная проверка неудачна — выход, уровень строгости фреймворка на этот раз повышается как минимум до 1
epsdk run main.py --strict

# Временный мягкий режим (в конфигурации включен strict_mode, но на этот раз хочется запустить)
epsdk run main.py --no-strict

Предварительная проверка перед запуском: run перед запуском быстро проверяет разбор config/config.toml и обязательную конфигурацию установленных компонентов, строгость по умолчанию следует ErisPulse.framework.strict_mode (при не 0 проверка неудачна — выход, при 0 только предупреждение и продолжение). Отсутствие файла конфигурации считается нормальным для первого запуска, только предупреждение, не ошибка. --strict временно включает: предварительная проверка неудачна — выход, при этом уровень строгости фреймворка на этот раз повышается как минимум до 1 (пропуск некорректных компонентов, передается через ERISPULSE_FRAMEWORK_STRICT_MODE в процесс запуска, не записывается в файл конфигурации); --no-strict наоборот временно понижает до мягкого. При ошибке самой предварительной проверки автоматически пропускается, не включает проверку сети, не блокирует запуск.

Команды управления проектом

Команда Алиас Параметры Описание
init — [путь] [--project-name/-n <имя>] [--path <каталог>] [--adapter/-a <имя>] [--quick/-q] [--force/-f] [--here] [--no-uv] [--no-venv] Инициализация проекта ErisPulse
create — {module,adapter,pack} [--name/-n <имя>] [--description/-d <описание>] [--author/-a <имя>] [--email/-e <почта>] [--homepage <url>] [--output/-o <каталог>] [--force/-f] [--local] Создание шаблона модуля/адаптера; pack преобразует локальный плагин в публикуемый проект

init

Инициализация нового проекта ErisPulse. Поддерживает интерактивный и быстрый режим, начиная с 2.8.4 генерирует pyproject.toml (список зависимостей), по желанию создает виртуальное окружение проекта .venv и устанавливает фреймворк и адаптер, а также поддерживает указание произвольного каталога.

Параметры:

Параметр Короткий Описание
[путь] Целевой путь (может включать родительский каталог, например ../apps/mybot; чистое имя эквивалентно --project-name)
--project-name -n Имя проекта
--path Родительский каталог проекта (в сочетании с -n указывает место создания)
--adapter -a Предварительно выбранный адаптер для установки (можно передавать несколько раз или через запятую), при передаче пропускает запрос и выбор адаптера
--quick -q Режим быстрой инициализации, пропуск интерактивного визуального интерфейса (по умолчанию создает .venv и устанавливает зависимости)
--force -f Принудительное перезапись существующих файлов конфигурации
--here Инициализация в текущем каталоге, без создания подкаталога
--no-uv Использовать pip вместо uv
--no-venv Пропуск создания виртуального окружения и установки зависимостей

Примеры:

# Интерактивная инициализация
epsdk init

# Быстрая инициализация (создание my_bot/ в текущем каталоге, с pyproject.toml + .venv)
epsdk init -q -n my_bot

# Быстрая инициализация с предварительной установкой адаптера (без интерактива, для скриптов / CI)
epsdk init -q -n my_bot --adapter yunhu,telegram

# Инициализация в произвольном каталоге (../apps/mybot)
epsdk init ../apps/mybot

# Комбинация родительского каталога и имени проекта
epsdk init -n my_bot --path ../apps

# Принудительная перезапись существующих конфигурационных файлов
epsdk init -f

# Инициализация в текущем каталоге
epsdk init --here -n my_bot

# Создание только структуры проекта, без виртуального окружения
epsdk init --no-venv -n my_bot

Результат инициализации: main.py, pyproject.toml (список зависимостей), config/config.toml + config.full.example, config/ssl/, logs/, .gitignore, README.md; при выборе создания виртуального окружения дополнительно генерируется .venv и устанавливает erispulse и выбранные адаптеры в него.

Note

.gitignore представляет собой шаблон с группировкой: байт-коды и результаты сборки Python, виртуальные окружения и .env, кэш инструментов, файлы редактора и системы, и полностью исключает каталоги config/ и logs/, поскольку config.toml содержит токены адаптеров и другие чувствительные данные, не рекомендуется добавлять в репозиторий; для обмена шаблоном конфигурации используйте config.full.example.

Warning

Не используйте uv run epsdk run для запуска робота. uv run при выполнении в каталоге без pyproject.toml создает одноразовое изолированное окружение — в нем через epsdk install установленные адаптеры не сохраняются. Пожалуйста, используйте epsdk run в каталоге проекта (автоматически использует .venv проекта), или сначала активируйте виртуальное окружение и затем запускайте.

create

Создание шаблона проекта модуля или адаптера ErisPulse; подкоманда pack преобразует локальный плагин (plugins/ каталог) в публикуемый стандартный проект.

Параметры:

Параметр Короткий Описание
{module,adapter,pack} Тип создаваемого объекта: module / adapter / pack (преобразование плагина в проект)
--name -n Название проекта (в PascalCase)
--description -d Описание проекта
--author -a Имя автора
--email -e Электронная почта автора
--homepage URL-адрес проекта
--output -o Каталог вывода (по умолчанию текущий каталог)
--force -f Принудительная перезапись существующего каталога
--local Создание локального плагина (module / adapter доступно): генерация структуры пакета plugins/<имя>/, без установки в пакет

Примеры:

# Интерактивное создание (вывод подсказки для выбора типа и заполнения информации)
epsdk create

# Прямое создание проекта Module
epsdk create module -n MyModule

# Создание локального плагина (в каталоге проекта plugins/, автоматически обнаруживается при запуске)
epsdk create module -n MyModule --local

# Создание локального плагина адаптера (аналогично, без установки в пакет для разработки)
epsdk create adapter -n MyAdapter --local

# Прямое создание проекта Adapter
epsdk create adapter -n MyAdapter

# Преобразование локального плагина в публикуемый проект (интерактивный выбор плагина → дополнение метаинформации → генерация стандартного проекта)
epsdk create pack

# Полные параметры
epsdk create module -n MyModule -d "Описание модуля" -a "Автор" -e "mail@example.com"

# Указание каталога вывода
epsdk create module -n MyModule -o ./projects

# Принудительная перезапись существующего каталога
epsdk create module -n MyModule -f

Команды языка

Команда Алиас Параметры Описание
i18n language, lang [язык] [--list/-l] Просмотр или смена языка отображения CLI

i18n

Просмотр текущего языка CLI, список поддерживаемых языков, смена языка отображения. Если параметр не указан, запускается интерактивное окно выбора.

Алиас: language, lang

Параметры:

Параметр Короткий Описание
[язык] Код языка для смены (например, zh-CN, en, ja, ru)
--list -l Вывести список всех поддерживаемых языков

Примеры:

# Интерактивный выбор языка
epsdk i18n

# Смена на английский
epsdk i18n en

# Смена на японский
epsdk i18n ja

# Вывести список всех поддерживаемых языков
epsdk i18n --list

Команды типовых аннотаций

Команда Алиас Параметры Описание
types t, stub [--output/-o <путь>] [--force] [--adapters-only] [--modules-only] Генерация файлов аннотаций типов для поддержки автодополнения в IDE

types

Сканирует установленные модули и адаптеры ErisPulse, генерирует файлы аннотаций типов .pyi, обеспечивая точное автодополнение и проверку типов в IDE.

Алиас: t, stub

Параметры:

Параметр Короткий Описание
--output -o Путь вывода (по умолчанию ep-stubs/ в текущем каталоге)
--force Принудительная перезапись существующих файлов аннотаций
--adapters-only Генерировать только аннотации для адаптеров
--modules-only Генерировать только аннотации для модулей

Примечание: --adapters-only и --modules-only взаимоисключаются, при одновременном указании применяется последний.

Примеры:

# Генерация аннотаций типов для всех установленных модулей и адаптеров
epsdk types

# Генерация только аннотаций для адаптеров
epsdk types --adapters-only

# Вывод в указанный каталог
epsdk types -o ./typings

# Принудительная перезапись существующих файлов
epsdk types --force

Глобальные параметры

Следующие параметры применимы ко всем командам:

Параметр Короткий Описание
--help -h Показать справку
--version -V Показать информацию о версии
--verbose -v Показать подробный вывод (можно добавлять -vv/-vvv)
--no-color Отключить цветной вывод (подходит для CI / сбора логов)
--no-banner Пропустить баннер запуска (сценарии / CI; в неинтерактивных терминалах и при ERISPULSE_NO_BANNER=1 автоматически скрыт)
--yes -y Автоматическое подтверждение всех интерактивных подсказок (непервичный режим)

Диагностика среды

doctor

Note

Эта команда требует ErisPulse 2.7.0+.

Диагностика текущей среды CLI, вывод отчета о состоянии. Используется для решения проблем "почему не устанавливается / не подключается".

Параметр Описание
--verbose Показать подробную информацию диагностики
--fix После диагностики попытаться автоматически исправить исправимые проблемы

Проверяемые пункты:

  • Python: версия и путь интерпретатора
  • Установщик: используется uv или pip
  • Целевой интерпретатор: среда, куда фактически установлены пакеты
  • Конфигурационный файл: существует ли config/config.toml
  • Конфигурация компонентов: полнота декларативной конфигурации установленных компонентов ("установлено, но не запускается" часто из-за отсутствующих обязательных полей)
  • Соединение с PyPI: доступность PyPI (и отображение найденных компонентов)
  • Системный прокси: обнаружен ли прокси

Автоматическое исправление (--fix):

  • config.toml отсутствует → генерируется начальный конфигурационный файл на текущем языке (тот же источник, что и init)
  • Конфигурация компонента "незавершена" → поочередно запускает интерактивный визуальный интерфейс для заполнения обязательных полей (в неинтерактивной среде советуется использовать epsdk config <имя>)
  • Проблемы с низкой версией Python, недоступностью PyPI и т.д. требуют ручного вмешательства → выводятся рекомендации
# Диагностика среды
epsdk doctor

# Использование алиаса
epsdk diag

# Диагностика и попытка автоматического исправления
epsdk doctor --fix

Интерактивная установка

При запуске epsdk install без указания имени пакета запускается интерактивная установка:

epsdk install

Интерактивное окно предоставляет:

  1. Выбор адаптера
  2. Выбор модуля
  3. Пользовательская установка

Распространённые случаи использования

Установка модуля

# Установка одного модуля
epsdk install Weather

# Установка нескольких модулей
epsdk install Yunhu Weather

# Обновление модуля
epsdk install Weather -U

Вывод списка компонентов

# Вывести все компоненты
epsdk list

# Вывести только адаптеры
epsdk list -t adapters

# Вывести только обновляемые компоненты
epsdk list -o

# Посмотреть доступные удалённые компоненты
epsdk list-remote

Удаление компонентов

# Удалить один компонент
epsdk uninstall Weather

# Удалить несколько компонентов
epsdk uninstall Yunhu Weather

Настройка компонентов

# Посмотреть статус конфигурации
epsdk config --list

# Интерактивный выбор цели для настройки
epsdk config

# Настройка указанного адаптера
epsdk config yunhu

Обновление компонентов

# Обновить все компоненты
epsdk upgrade

# Обновить указанный компонент
epsdk upgrade Weather

# Принудительное обновление
epsdk upgrade -f

Запуск проекта

# Обычный запуск
epsdk run main.py

# Горячая перезагрузка
epsdk run main.py --reload

Смена языка

# Интерактивный выбор языка
epsdk i18n

# Прямая смена на английский
epsdk i18n en

# Вывести список поддерживаемых языков
epsdk i18n --list

Генерация аннотаций типов

# Генерация всех аннотаций типов
epsdk types

# Генерация только аннотаций типов модулей
epsdk types --modules-only

Инициализация проекта

# Интерактивная инициализация
epsdk init

# Быстрая инициализация
epsdk init -q -n my_bot

Создание шаблона

# Интерактивное создание (вывод подсказки для выбора типа и заполнения информации)
epsdk create

# Прямое создание проекта Module
epsdk create module -n MyModule

# Прямое создание проекта Adapter
epsdk create adapter -n MyAdapter

# Полные параметры
epsdk create module -n MyModule -d "Описание модуля" -a "Автор" -e "mail@example.com"

# Принудительная перезапись существующего каталога
epsdk create module -n MyModule -f
