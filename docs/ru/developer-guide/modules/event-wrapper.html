Справочник по Event-обёртке

Note

Обязательное чтение для разработчиков модулей — одна из пяти ключевых статей из раздела "Путь к разработке" на главной странице. Необходимо для разработки модулей.

Параметр event в обработчиках событий может напрямую вызывать .get_text() / .reply() / .wait_reply(), благодаря Event-обёртке. В этой статье представлен полный список методов — при написании обработчиков событий обращайтесь к ней по необходимости, все методы и их поведение описаны здесь.

Добавление аннотации типа к параметру event

Параметр event в обработчиках событий является Event-обёрткой (подклассом dict). Рекомендуется добавлять аннотацию типа Event (при выполнении без аннотации работает, но аннотация полезна для автодополнения в IDE и статической проверки):

from ErisPulse.Core.Event import Event

@message.on_private_message()
async def handler(event: Event):
    text = event.get_text()   # IDE автоматически подсказывает все удобные методы
    await event.reply(text)   # Опечатки в статической проверке будут обнаружены

Без аннотации IDE не распознаёт методы Event (get_text() / reply() / wait_reply() / расширения для платформы), и приходится полагаться на собственные знания.

Обратите внимание: event в колбэке обработчика событий — это Event-обёртка (аннотация Event); event в методах жизненного цикла модуля on_load / on_unload — это обычный dict (аннотация dict), не путайте их.

Основные особенности

  • Полная совместимость с dict: Event наследуется от dict
  • Удобные методы: Предоставляет множество удобных методов
  • Доступ через точку: Поддерживает доступ к полям события через точку
  • Совместимость с предыдущими версиями: Все методы являются необязательными

Основные методы полей

from ErisPulse.Core.Event import command, Event

@command("info")
async def info_command(event: Event):
    event_id = event.get_id()
    platform = event.get_platform()
    time = event.get_time()
    print(f"ID: {event_id}, платформа: {platform}, время: {time}")

@message.on_group_message()
async def group_handler(event: Event):

Функция ответа

from ErisPulse.Core.Event import command, Event

@command("ask")
async def ask_command(event: Event):
    await event.reply("Введите ваше имя:")
    reply = await event.wait_reply(timeout=30)
    if reply:
        name = reply.get_text()
        await event.reply(f"Привет, {name}!")

@command("price")
async def price_command(event: Event):
    await event.reply("Введите сумму (например: 5 юаней):")
    # Ответ должен соответствовать регулярному выражению, иначе ожидание продолжится до истечения тайм-аута
    reply = await event.wait_reply(timeout=30, regex=r"\d+\s*元")
    if reply:
        await event.reply(f"Получена сумма: {reply.get_text()}")

reply и send_chain

Для случаев, когда reply() не подходит — специфичные методы платформы (например, Expire/Board), последовательные модификаторы, отправка без параметров содержимого — используйте event.send_chain, чтобы получить цепочку отправки с уже установленной целью и аккаунтом отправки, и свободно добавляйте модификаторы перед отправкой:

await event.send_chain.At(event.user_id).Text("Содержимое")     # Цепочка модификаторов + отправка

Список методов модификаторов см. в Спецификации методов отправки.

Расширенные возможности интерактивной сессии

Note

Эти возможности требуют ErisPulse 2.8.0+.

# Напоминание в сессии: если 5 минут без ответа, напомнить, при ответе отменить напоминание
reminder = event.remind(300, "Еще здесь? Если не хочешь общаться, напиши «выход»")
reminder.cancel()  # Также можно отменить вручную

# Повышение при таймауте: по истечении времени обязательно выполнить действие (не отменяется ответом), например, уведомить владельца о превышении времени обработки
event.escalate(1800, lambda e: notify_master("Заявка просрочена"))

# Ожидание нескольких путей: одновременно ждать "согласия" и "отказа", сработает первый пришедший
which, reply = await event.select(
    event.expect(pattern="согласен*", user="10001"),
    event.expect(pattern="отказ*", user="10002"),
    timeout=60,
)
if which is None:
    await event.reply("Тайм-аут, ответ не получен")

# Ожидание в сессии: ответ от любого пользователя в группе может быть принят (для группового сотрудничества)
reply = await event.wait_reply(session=True, prompt="Кто-нибудь, помогите ответить?")

# Ящик сообщений сессии: последние 20 сообщений текущей сессии (включая сообщения бота, контекст для ИИ, база для предотвращения повторений)
messages = await event.history(20)

# Транзакция сообщений: при возникновении исключения автоматически отменяются отправленные сообщения в рамках транзакции
async with event.message_tx():
    await event.reply("Обработка, подождите...")
    result = await do_something()
    await event.reply(f"Завершено: {result}")

Справочник методов

Основные методы

Основная информация о событии

  • get_id() - Получить идентификатор события
  • get_time() - Получить метку времени события (Unix, секунды)
  • get_type() - Получить тип события (message/notice/request/meta)
  • get_detail_type() - Получить подробный тип события (private/group/friend и т.д.)
  • get_platform() - Получить название платформы

Информация о боте

  • get_self_platform() - Получить название платформы бота
  • get_self_user_id() - Получить идентификатор пользователя бота
  • get_self_account_id() - Получить идентификатор аккаунта бота (режим множественных ботов)
  • get_self_info() - Получить полную информацию о боте в виде словаря

Идентификаторы сессии

  • get_target_id() - Получить уникальный идентификатор цели (для групповых сообщений возвращает group_id, для каналов channel_id, для личных сообщений user_id, в порядке group → channel → guild → thread → user возвращает первый непустой)
  • get_session_id() - Получить уникальный идентификатор сессии, формат: {platform}:{detail_type}:{target_id}

Методы сообщений

Содержимое сообщения

  • get_message() - Получить массив сегментов сообщения (формат OneBot12)
  • get_alt_message() - Получить альтернативный текст сообщения
  • get_text() - Получить текстовое содержимое (альтернативное имя get_alt_message())
  • get_message_text() - Получить текстовое содержимое (альтернативное имя get_alt_message())

Информация о отправителе

  • get_user_id() - Получить идентификатор пользователя отправителя
  • get_user_nickname() - Получить никнейм отправителя
  • get_sender() - Получить полную информацию об отправителе в виде словаря

Информация о группе/канале

  • get_group_id() - Получить идентификатор группы (для сообщений в группе)
  • get_channel_id() - Получить идентификатор канала (для сообщений в канале)
  • get_guild_id() - Получить идентификатор сервера (для сообщений на сервере)
  • get_thread_id() - Получить идентификатор темы/подканала (для сообщений в теме)

Связанные с упоминаниями

  • has_mention() - Содержит ли сообщение упоминание бота
  • get_mentions() - Получить список всех упомянутых идентификаторов пользователей

Определение типа сообщения

Основные проверки

  • is_message() - Является ли событием сообщения
  • is_private_message() - Является ли личным сообщением
  • is_group_message() - Является ли групповым сообщением
  • is_at_message() - Является ли сообщением с упоминанием (альтернативное имя has_mention())

Методы уведомлений

Информация об операторе

  • get_operator_id() - Получить идентификатор оператора
  • get_operator_nickname() - Получить никнейм оператора

Определение типа уведомления

  • is_notice() - Является ли уведомлением
  • is_group_member_increase() - Уведомление о добавлении участника в группу
  • is_group_member_decrease() - Уведомление об удалении участника из группы
  • is_friend_add() - Уведомление о добавлении друга (соответствует detail_type == "friend_increase")
  • is_friend_delete() - Уведомление об удалении друга (соответствует detail_type == "friend_decrease")

Методы запросов

Информация о запросе

  • get_comment() - Получить комментарий к запросу

Определение типа запроса

  • is_request() - Является ли запросом
  • is_friend_request() - Является ли запросом на добавление друга
  • is_group_request() - Является ли запросом на группу

Утверждение/отклонение запроса (approve / reject)

Регистрация обработчика запроса и принятие решения:

from ErisPulse.Core.Event import request

@request.on_friend_request()
async def handle_friend(event):
    request_id = event.get_request_id()   # Идентификатор запроса (при отсутствии вызовет ValueError)
    if event.get_comment() == "пароль":
        result = await event.approve()    # Принять (можно с комментарием: approve(comment="добро пожаловать")）
    else:
        result = await event.reject()     # Отклонить
    if result.get("status") != "ok":
        # Стандартный формат ответа, при ошибке message объясняет причину (например, 34001 запрос просрочен)
        pass

@request.on_group_request()               # Запрос на группу / приглашение
async def handle_group(event):
    await event.approve()

Действия утверждения/отклонения выполняются через DSL адаптера Request; формат ответа, коды ошибок и требования к реализации адаптера см. в Спецификации действий запроса. Также доступен универсальный регистратор request.on_request() (без различения типа).

Управление цепочкой (done / is_processed / is_stopped)

  • done(claim=True) - Заявить (по умолчанию) или просто заблокировать последующие обработчики с низким приоритетом
  • is_processed() - Было ли событие уже заявлено
  • is_stopped() - Была ли цепочка обработки события заблокирована

Полная семантика заявки и блокировки (взаимодействие приоритетов, заявка команды) см. в Введение в обработку событий · Управление цепочкой: заявка и блокировка.

Функция ответа

Основной ответ

  • reply(content, method="Text", at_sender=False, quote=False, at_users=None, reply_to=None, at_all=False, via=None, **kwargs) - Общая функция ответа

    • content: Содержимое для отправки (текст, URL и т.д.)
    • method: Метод отправки, по умолчанию "Text", можно выбрать "Image"/"Voice"/"Video"/"File" и т.д.
    • at_sender: Упоминать ли отправителя (автоматически извлекает user_id)
    • quote: Ссылаться ли на текущее сообщение (автоматически извлекает message_id)
    • at_users: Список упоминаний пользователей, например ["user1", "user2"]
    • reply_to: Ручная установка ID сообщения для ответа
    • at_all: Упоминать ли всех участников
    • **kwargs: Дополнительные параметры (например, user_id для метода Mention)

  • reply_ob12(message) - Использовать OneBot12-сегменты сообщения для ответа

    • message: Список или словарь OneBot12-сегментов, можно использовать MessageBuilder для построения

Проверка поддержки платформой

  • supports(method) - Проверить, поддерживает ли платформа метод отправки (например, "Image", "Voice"), возвращает bool
  • available_methods() - Перечислить все доступные методы отправки на текущей платформе, возвращает список методов

Функция пересылки

Внимание: Функция пересылки должна реализовываться через DSL Send адаптера, Event-обёртка сама не предоставляет прямых методов пересылки.

# Переслать сообщение в группу
adapter = sdk.adapter.get(event.get_platform())
target_id = event.get_group_id()  # или указать другой ID группы
await adapter.Send.To("group", target_id).Text(event.get_text())

Многоконтурная настройка: При отправке в рамках цепочки обработки события не нужно явно указывать аккаунт — фреймворк вводит идентификатор аккаунта, вызвавшего событие, в контекст вызова, и Send / Api / Request цепочки автоматически привязываются к аккаунту, вызвавшему событие (явное использование Using() всегда имеет приоритет; в сценариях таймеров и без контекста события используется аккаунт по умолчанию). То есть пример выше отправит сообщение от аккаунта, получившего это событие, без дополнительного кода.

Повторное получение в рамках одного аккаунта

При наличии нескольких аккаунтов в одной группе одно физическое сообщение может быть получено несколькими аккаунтами. Фреймворк обрабатывает это по ErisPulse.framework.cross_account_policy (по умолчанию off, не связывает):

  • mark: Последующие копии по-прежнему распределяются, но в верхнем уровне события вставляется поле multi_receipt ({"event_id": id первого обработанного события, "self_id": первый обработанный аккаунт}) — модули могут читать это поле и самостоятельно решать, пропускать ли ответ
  • drop: Копии отбрасываются на входе распределения, модули не замечают
  • Приоритет упоминания: Копии, в которых цель упоминания совпадает с идентичностью аккаунта (self.user_id / self.account_id), не участвуют в ассоциации (не вставляется multi_receipt, не отбрасываются) — модули, отслеживающие события с упоминанием (on_at_message), всегда получают свои события
  • Привязка аккаунта к сессии: ErisPulse.framework.session_accounts может точно привязать сессию к единственному аккаунту (только аккаунт, к которому привязана сессия, получает события, остальные копии отбрасываются; независимо от политики, приоритет упоминания сохраняется)

Функция ожидания ответа

  • wait_reply(prompt=None, timeout=60.0, callback=None, validator=None, method="Text", pattern=None, regex=None) - Ожидание ответа пользователя
    • prompt: Подсказка, если указана, отправляется пользователю
    • timeout: Время ожидания (секунды), по умолчанию 60 секунд
    • callback: Колбэк, выполняется при получении ответа
    • validator: Функция проверки, используется для проверки, является ли ответ действительным
    • method: Метод отправки, по умолчанию "Text"
    • pattern: Глоб-шаблон (* / ? / [seq]), текст ответа должен соответствовать, иначе ожидание продолжается
    • regex: Регулярное выражение, текст ответа должен соответствовать (один из pattern или regex), иначе ожидание продолжается
    • Возвращает Event-объект пользователя, при таймауте возвращает None

Интерактивные методы

  • confirm(prompt=None, timeout=60.0, yes_words=None, no_words=None, method="Text", hint=False) - Подтверждение диалога

    • Возвращает True (подтверждение) / False (отрицание) / None (таймаут)
    • Встроенные английские и китайские слова подтверждения автоматически распознаются, можно настроить собственный набор слов
    • method: Метод отправки, по умолчанию "Text"; поддерживает "Image"/"Markdown" и другие не текстовые методы отправки подсказки
    • hint: Добавлять ли автоматически подсказку с словами подтверждения в конец подсказки (например, "（да/нет）"），по умолчанию False

  • choose(prompt, options, timeout=60.0, method="Text", options_format="auto", merge_prompt=False, placeholder="{options}") - Выбор меню

    • options: Список текстов опций
    • Возвращает индекс опции (0-based), при таймауте возвращает None
    • method: Метод отправки, по умолчанию "Text"; текстовые методы (Text/Markdown/md/Html/h5) по умолчанию объединяют опции в конец
    • options_format: Формат опций (по умолчанию: "auto", автоматически выбирается встроенный стиль в зависимости от method)
      • "auto": Markdown→неупорядоченный список (- 1. Опция), Html→упорядоченный список (<ol>), другие→простой список
      • "list": Каждая опция на отдельной строке, например 1. Опция A\n2. Опция B
      • "inline": Опции отображаются в одной строке, например 1.A | 2.B
      • "md": Markdown неупорядоченный список
      • "html": Html упорядоченный список
      • callable: Пользовательская функция, принимает list[str] и возвращает str
    • merge_prompt: Принудительно объединять в одно сообщение, по умолчанию False
      • False (по умолчанию): Текстовые методы объединяют автоматически; не текстовые методы сначала отправляют prompt, затем Text-опции
      • True: Независимо от method объединяются в одно сообщение, отправляется с указанным method
    • placeholder: Заполнитель для вставки опций, по умолчанию {options}; если в prompt встречается этот маркер, он заменяется на текст опций, если пустая строка, то всегда добавляется в конец

  • collect(fields, timeout_per_field=60.0) - Сбор анкеты

    • fields: Список полей, каждое поле содержит key, prompt, необязательный validator, необязательный method
    • Возвращает словарь {key: value}, при таймауте любого поля возвращает None
    • Каждое поле может иметь ключ method для указания метода отправки, например, для сбора изображения: {"key": "avatar", "prompt": "Отправьте аватарку", "method": "Image"}
    • Каждое поле может иметь ключ options (список), при наличии превращается в выбор (автоматически вызывается логика choose)
    • Каждое поле может иметь ключи options_format, merge_prompt, placeholder, управляющие форматом опций, поведением объединения сообщений и заполнителем

  • wait_for(event_type="message", condition=None, timeout=60.0) - Ожидание произвольного события

    • condition: Фильтрующая функция, возвращает True при совпадении
    • Возвращает Event-объект, при таймауте возвращает None

  • conversation(timeout=60.0) - Создание контекста многошагового диалога

    • Возвращает объект Conversation, поддерживающий say()/wait()/confirm()/choose()/collect()/stop()
    • Свойство is_active указывает, активен ли диалог

Примеры интерактивных методов

confirm() - Подтверждение диалога:

from ErisPulse.Core.Event import Event
@command("delete", help="Удалить данные")
async def delete_handler(event: Event):
    if await event.confirm("Вы действительно хотите удалить все данные?"):
        sdk.storage.delete("all_data")
        await event.reply("Данные удалены")
    else:
        await event.reply("Отменено")

confirm() - С подсказкой:

# hint=True добавит в конец подсказки "（да/нет）"
if await event.confirm("Продолжить?", hint=True):
    await event.reply("Продолжено")
# Пользователь увидит: Продолжить?（да/нет）

choose() - Выбор меню:

from ErisPulse.Core.Event import Event
@command("color", help="Выбрать цвет")
async def color_handler(event: Event):
    choice = await event.choose("Выберите цвет:", ["красный", "зеленый", "синий"])
    if choice is not None:
        colors = ["красный", "зеленый", "синий"]
        await event.reply(f"Вы выбрали: {colors[choice]}")

choose() - Форматирование и объединение сообщений:

# inline формат: опции отображаются в одной строке
choice = await event.choose("Выберите:", ["A", "B", "C"], options_format="inline")
# Вывод: 1.A | 2.B | 3.C

# Пользовательская функция форматирования
choice = await event.choose("Выберите:", ["кот", "собака"],
    options_format=lambda opts: " / ".join(opts))
# Вывод: кот / собака

# options_format="auto" (по умолчанию): автоматически выбирается встроенный стиль в зависимости от method
# Markdown → неупорядоченный список
choice = await event.choose(
    "## Выберите", ["кот", "собака"],
    method="Markdown",  # auto автоматически распознает как md-список
)
# Вывод:
# ## Выберите
# - 1. кот
# - 2. собака

# Html → упорядоченный список
choice = await event.choose(
    "<h2>Выберите</h2>", ["кот", "собака"],
    method="Html", merge_prompt=True,  # auto автоматически распознает как html-список
)
# Вывод:
# <h2>Выберите</h2>
# <ol><li>1. кот</li><li>2. собака</li></ol>

# Режим объединения + заполнитель
choice = await event.choose(
    "## Выберите\n{options}\nОтветьте номером",
    ["кот", "собака"],
    method="Markdown", merge_prompt=True,
)

# Пользовательский заполнитель
choice = await event.choose(
    "Выберите: [choices]",
    ["кот", "собака"],
    placeholder="[choices]",
)

collect() - Сбор анкеты:

from ErisPulse.Core.Event import Event
@command("register", help="Зарегистрироваться")
async def register_handler(event: Event):
    data = await event.collect([
        {"key": "name", "prompt": "Введите имя:"},
        {"key": "age", "prompt": "Введите возраст:",
         "validator": lambda e: e.get_text().isdigit()},
    ])
    if data:
        await event.reply(f"Успешно зарегистрированы! {data['name']}, {data['age']} лет")

reply с не-Text методами:

Платформенные расширения

Адаптеры могут регистрировать платформенно-специфичные методы для Event-обёртки. Методы доступны только на Event-экземплярах соответствующей платформы, на других платформах вызов приведёт к AttributeError.

Методы через Event.__getattribute__ имеют приоритет над встроенными методами, поэтому можно переопределить confirm/choose/collect/wait_reply и предоставить платформенно-специфичную реализацию (например, с кнопками, карточками). Встроенная реализация доступна как _builtin_* функции для переопределения.

# Почтовое событие - только методы почты
event = Event({"platform": "email", "email_raw": {"subject": "Hello"}})
event.get_subject()      # ✅ Возвращает "Hello"
event.get_chat_type()    # ❌ AttributeError

# Telegram событие - только методы Telegram
event = Event({"platform": "telegram", "telegram_raw": {"chat": {"type": "private"}}})
event.get_chat_type()    # ✅ Возвращает "private"
event.get_subject()      # ❌ AttributeError

# Встроенные методы доступны всегда
event.get_text()         # ✅ На любой платформе
event.reply("hi")        # ✅ На любой платформе

Проверка зарегистрированных методов

from ErisPulse.Core.Event import get_platform_event_methods

methods = get_platform_event_methods("email")
# ["get_subject", "get_from", ...]

Поддержка hasattr и dir

hasattr(event, "get_subject")   # Только когда platform="email" возвращает True
"get_subject" in dir(event)     # То же самое

Кросс-платформенное расширение (шаблон)

register_event_method и register_event_mixin поддерживают передачу "*" в качестве названия платформы, регистрируя методы, доступные на всех платформах. Подходит для AI-диалогов, управления контекстом и других функций, требующих кросс-платформенной переиспользования.

from ErisPulse.Core.Event.wrapper import register_event_method

@register_event_method("*")
async def ai_chat(self, prompt: str):
    # self — экземпляр Event, доступен к данным события и встроенным методам
    await self.reply(f"AI: {prompt}")

После регистрации любой обработчик события на любой платформе может вызывать event.ai_chat(...).

Приоритет методов (от высшего к низшему): методы платформы → методы шаблона → встроенные методы → доступ по ключу словаря.

Способ регистрации расширений адаптерами см. в API системы событий - Кросс-платформенное расширение шаблоном.
